# Database and recovery tests

`testing_install.py write|read --endpoint URL --state FILE` exercises a fresh testing installation with boto3. Set `MOKYU_TEST_ALLOW_STATE_CHANGES=isolated-only`, run the write phase, restart the server on the same data directory and run the read phase with the same state file.

`local_write_memory.py` starts and kills its own fault-injection binary. Set the same isolation guard, `MOKYU_TEST_BINARY` and a writable `MOKYU_TEST_WORKDIR`. It checks budget fallback, source quarantine, interrupted disk sync, explicit flush and clean shutdown.

[Test guide](../README.md) · Run commands from the repository root. Short test paths such as `fixtures/` are relative to `tests/`.

## Single control status

Run `python -m tests.recovery.single_control_status single_control --counts 2 1 0 1` on an isolated primary with one ready data node and its registered worker offline after handoff. Counts are registered peers, ready data peers, ready worker peers and remote ownership (0 or 1). Supply `MOKYU_TEST_BINARY`, `MOKYU_TEST_CONFIG`, `MOKYU_TEST_WEB` and the tester account's `MOKYU_TEST_PASSWORD`. Check `single` after switching back. Repeat on each supported database.

## Bootstrap and native contracts

Validate database changes on PostgreSQL 18, MySQL 8.0.19 and MariaDB 10.6.3 as well as supported maintenance releases. Run all MySQL contracts against MariaDB with `MOKYU_TEST_MYSQL_CONFIG`. `mysql_dialect_and_lock_scope_contract` checks JSON, case/trailing-space comparisons and claim lock scope. `migrations.py` checks refusal before writes on empty PostgreSQL 17 and bootstrap, restart and history validation on supported PostgreSQL. Run `mysql_write_cleanup_skips_busy_receipts` to check expiry and pruning against a concurrent writer. Run `mysql_work_recovery_skips_live_tasks` to check that recovery queues only expired work owned by the current task token. Run `mysql_read_cleanup_preserves_busy_grants` for concurrent read renewal and expiry. Each test needs a separate fresh database.

`postgres_schema_bootstrap_contract` and `mysql_schema_bootstrap_contract` compare snapshots with the full migration chain, including structure, seeds, checksums, restart, damaged history, future versions, failed initialization and real disconnects. Rejection must leave all rows, structure and history intact. PostgreSQL also races initializers. The fixture user must be able to create `mokyu_bootstrap_*` databases on a disposable server; dispose of them with the test instance. For MySQL/MariaDB start with an empty utf8mb4/utf8mb4_bin database. `sqlite_schema_bootstrap_contract` uses bundled in-memory SQLite and runs by default; `sqlite_runtime_and_migration_recovery` covers files, WAL and process recovery.

With each new timestamp migration, regenerate the matching `src/model/backend/{postgres,mysql,sqlite}/schema.sql` snapshot and update its initializer version. Snapshots contain final structure and required seeds. The initializer records the version and `_sqlx_migrations` last. Retain published migration bytes and checksums. Compare columns, defaults, constraints, indexes and views, plus PostgreSQL functions, triggers and sequences.

For MySQL authentication restart the database cold, then start Mokyu before any other client primes the auth cache. Without TLS, the first `caching_sha2_password` authentication needs SQLx's `mysql-rsa` feature.

`cleanup_reacquires_returning_connection`, `cleanup_yields_to_busy_writer_and_recovers`, `cleanup_propagates_pool_errors` and `cleanup_cancels_busy_database_transaction` are ordinary Rust tests. They use disposable SQLite files and a single write connection to check repeated cleanup claims, bounded backoff and recovery, cancellation during a contended BEGIN and propagation of real pool errors.

`sqlite_synchronous_contract` checks FULL by default and after bootstrap, saved FULL/NORMAL/OFF across writer and all reader connections, reconnect, rollback, a single connection and invalid values. `sqlite_nonce_durability_contract` checks temporary FULL for a NORMAL reservation, restoration, cancellation/commit boundaries, disjoint ranges and startup validation. The first reservation and switching to OFF exclude each other; existing reservations prevent OFF. Process exit does not simulate power loss.

`python -m tests.recovery.sqlite_sync` takes ownership of a stopped initialized service, using the recovery config, password file, fault directory and local storage root. Check saving, actual synchronous mode, restart and SIGKILL readback on SQLite. Other engines expose only common I/O settings. All four must return 409 for revision conflicts. `web/tests/sqlite-sync.spec.ts` exercises the three locales, sync/shutdown forms, cancellation, keyboard input and restart notices.

For `nonce_database_contract` provide a new database through `MOKYU_TEST_NONCE_CONFIG` and set `MOKYU_TEST_ALLOW_STATE_CHANGES=isolated-only`. Run `cargo test --features fault-injection nonce_database_contract -- --ignored --nocapture` independently on all four products. Check key-creation rollback, counters per domain, concurrent allocation, discarded unused ranges after restart and uniqueness of key material.

`python -m tests.recovery.nonce_ranges` owns a stopped initialized service and uses the source-quarantine config, password file, fault directory and S3 fixture. Check encrypted chunks/packs, no allocation on direct dedup, kills before/after commit, missing/exhausted counters, rotation and no allocation for plaintext or raw.

`key_replacement_contract` takes a fresh `MOKYU_TEST_CONFIG` and runs with `--ignored` on each product. Check disabled storage, scope/revision conflicts, audit rollback, concurrent confirmation, target validation, reconnect and retries of old operations.

`python -m tests.recovery.key_replacement` owns a stopped initialized source-quarantine fixture with `MOKYU_TEST_FSYNC_ROOT`. Check kills before/after commit, lost replies, old encrypted chunks/packs, dedup, retries after failed refresh and API/CLI identity isolation.

## Shutdown and durability

`python -m tests.recovery.shutdown_flush` owns the service and a dedicated S3 backend. Allocate at least 64 MiB of node disk cache, including 32 MiB for uploads. Check the database-time cutoff for each flush, CLI wait timeout without cancellation, SIGTERM drain, durable raw input while CDC is paused, exit deadlines and restart. Run separately on all four products; the service must have no other test clients.

`python -m tests.recovery.buffered_writes` and `python -m tests.recovery.buffered_chunks` own a stopped initialized single-container service, S3 backend and fsync fault fixture. Run each product separately; 128 MiB disk cache with 64 MiB for uploads is recommended. Check early acknowledgment, immediate read, durable copy/reuse, disabled/full cache fallback, failed file/directory sync, kill/restart, corruption, flush and shutdown. The raw suite checks durable intent before the first write and a policy change after source creation. The chunk suite covers multipart durability, encryption and background packing races. `web/tests/buffered-storage.spec.ts` checks locale, draft cancellation/save, keyboard and narrow screens.

`python -m tests.recovery.write_memory` uses the same exclusive service and S3 fixture with 8 MiB write memory and a 64 MiB file cache. Check checksum/disconnect release, raw/chunk RAM reads and ranges, last-reader charging, durable Copy/reuse, invalidation and retransmission after a kill, full-budget fallback and 503, failed flush retention, multipart, final packs, background CDC, shutdown drain and a zero budget.

`python -m tests.recovery.write_scheduling` owns the service plus S3 fixture on each database product. Check per-backend coalescing, parameter bounds and seconds normalization, forced raw/chunk drain, age rejection/synchronous fallback, isolation between backends, early flush at capacity, local fsync, forced restart and orderly shutdown.

`storage_diagnostics_count_shared_failures_and_cache_fallback` is an ignored Rust test with `fault-injection`. Supply a new `MOKYU_TEST_SQLITE_CONFIG`, a private `MOKYU_TEST_FAULT_DIR` and `MOKYU_TEST_ALLOW_STATE_CHANGES=isolated-only`. It covers 16 shared readers, missing sources, wrong/truncated bodies, corrupt entries that cannot be removed and missing cache files. Check that transfer, content and cache diagnostics remain distinct.

- `recovery/truncated_stream.py`: build 513 source-offset extents in dedicated PostgreSQL, remove the last extent and check full/tail reads with primed and bypassed caches. Neither may silently succeed; after restoration, bytes must match. Use `MOKYU_TEST_DATABASE_FILE` and publication-test endpoints.

- `recovery/file_identities.py`: own a stopped initialized service with the `source_quarantine` fixture and a separate S3 backend. Check durable UUIDs, file/cache paths, stable pack/unpack identity, rejection of wrong API ID types and reads after restart on each database product.

- `recovery/raw_crashes.py`: own the service, kill it around raw publication, lose replies, inject fsync EIO and reclaim orphans. Use the `local_durability.py` fsync environment.
- `recovery/file_permissions.py`: own a stopped initialized SQLite service. Run inside an isolated Linux container as root so the test can switch to UID 65534. Verify strict/permissive umask inheritance, 0644 payloads/pending files, 0755 directories, 0600 SQLite sidecars, multipart publication and restart. Use `source_quarantine` variables and unset `MOKYU_TEST_BACKEND`.
- `recovery/local_multipart.py`: own a stopped initialized `source_quarantine` service. Check candidate growth, inode reuse for contiguous layouts, sparse/replaced/selected parts, kills during upload/Complete and confirmation/mapping/reclaim, the two-batch backlog cap, abort and final asynchronous cleanup; verify SHA-256 and length after GC. For S3 write-cache reuse pass `--s3-cache` or `MOKYU_TEST_MULTIPART_CACHE=1` and provide `MOKYU_TEST_BACKEND` (recommended: 256 MiB cache, 128 MiB upload). Build `recovery/fsync.c`, set `LD_PRELOAD`, `MOKYU_TEST_FSYNC_FAULT` and `MOKYU_TEST_FSYNC_TRACE`; for S3 set the fault root to `<data_path>/pending/raw`. `MOKYU_TEST_SPACE_FAULT` injects low space and checks source retention and retry. `--cross-filesystem` requires `MOKYU_TEST_FSYNC_ROOT` on another filesystem from the instance multipart directory to check copy fallback. Unit tests cover asynchronous/cached probes, failed probes, direct copy and anonymous temporary cleanup. For a real clone/COW test use `real_reflink_preserves_sources_and_copy_on_write` with its own reflink-capable `MOKYU_TEST_REFLINK_DIR` and explicitly pass `--ignored`.
- `recovery/storage_policy.py`: initialize and stop an isolated instance; the test owns the process, using `source_quarantine.py` variables. Test backend policy/revision after restart, per-backend multipart deadlines, renewal only on writes, disk headroom isolation and memory admission. `*_storage_contract`, `*_maintenance_contract` and `postgres_storage_policy_expiration` cover rechecking in the transaction and active part leases.

- `recovery/multipart_completion.py`: on all four products and two data nodes, verify five-second Complete keepalives, errors in HTTP 200 XML, disconnect, joining an identical manifest, durable replay, restart and lease fencing. Use fault injection; set `MOKYU_TEST_COMPLETE_TIMEOUT_SECONDS=12` for fast tests or `300` for the actual deadline. Set both service and harness to the same deadline. The cluster also checks publication/cleanup races and remote acknowledgment of the local queue using kill/start markers. The test timeout is not a deployment option.

- `recovery/upload_cache.rs`: PostgreSQL two-executor upload preparation, cancellation rollback and atomic ownership, pins and source generations. Requires fault injection.
- `recovery/single_restart.py`: common API contract for the three backend implementations. Kill at ten checkpoints, including upload preparation commit boundaries; verify owner/pin recovery, rotation with pending data and post-restart reads of local/S3 encrypted objects.

`recovery/pack_memory.rs` requires fresh `MOKYU_TEST_SQLITE_CONFIG`, isolated `MOKYU_TEST_FAULT_DIR` and explicit state-change opt-in. Run `cargo test --locked --no-default-features --features fault-injection pack_memory_follows_blocking_work_and_last_reader -- --ignored --nocapture` without a service using the same database. It blocks real pack decode/check/encode/unpack, then verifies memory and CPU permits after cancel, timeout, error, panic, success and last-reader release.

`recovery/local_durability.py` injects real file and directory fsync errors on each single-container engine: failed initialization registers no storage, failed overwrite/rewrite preserves previous bytes and retry succeeds. In a Linux build container run `cc -shared -fPIC -Wall -Wextra -Werror tests/recovery/fsync.c -ldl -o /test/fsync.so`. Set `LD_PRELOAD=/test/fsync.so` only for the service under test. The service and test share `MOKYU_TEST_FSYNC_ROOT` (dedicated backend root without trailing slash), `MOKYU_TEST_FSYNC_FAULT` and `MOKYU_TEST_FSYNC_TRACE`; keep fault/trace files and the database outside that root. This tests fsync errors, not power loss. Local storage has no upload cache; `storage/single_lifecycle.py` covers unique S3 pending data and flush.

## Process fixtures

`python -m tests.recovery.publish_coordination` runs against the active single-container source-quarantine fixture for raw/chunk PUT, Copy and Complete. Pause sealing after publication: reads can proceed, ACK must wait, and delete/GC must honor active writer pins. `raw_crashes` checks recovery after killing at this boundary. For a negative comparison against an implementation known to block here, set `MOKYU_TEST_EXPECT_PUBLISH_BLOCKED=1`.

`python -m tests.recovery.received_publication` uses the same running-service fixture for each database. It checks raw/chunks PUT metadata, failed conditions, checksums, empty objects, old-version reads while publication is paused and write authorization revoked during upload. `raw_crashes` also kills the service before publication to verify recovery of fully received, unpublished content.

- `python -m tests.recovery.storage_relocation`: owns a stopped isolated service, copies one complete local namespace to an isolated S3 fixture and back, verifies maintenance/upload/read guards and crash boundaries. Set `MOKYU_TEST_RELOCATION_BACKEND` to the fixture credential file and the usual `source_quarantine` environment, without `MOKYU_TEST_BACKEND`.
- `python -m tests.recovery.raw_processing` owns a stopped initialized source-quarantine service. Run local and simulated S3 with all four products. Check idle raw workers do not swallow task notifications, durable ACK before dedup, retained receipt policy, two kill/restart checkpoints, active readers, multipart/Copy, delete and rejection of bad sources.

`raw_permit_order_cancellation_and_retry` uses a fresh `MOKYU_TEST_SQLITE_CONFIG`, an isolated `MOKYU_TEST_FAULT_DIR`, a disposable S3 `MOKYU_TEST_BACKEND` JSON file and `MOKYU_TEST_ALLOW_STATE_CHANGES=isolated-only`. Run `cargo test --locked --no-default-features --features fault-injection raw_permit_order_cancellation_and_retry -- --ignored --nocapture`. It schedules actual verified raw reads, the deduplication worker, raw writes and native Multipart uploads with one CPU/read/backend slot and one or three saturated global upload slots. It checks cancellation at both upload gates, CPU-wait cancellation, persisted processing retries, invalid digests and completed Multipart contents. The database and fault directory must not be shared with another service; use `raw_processing`, `raw_uploads` and `raw_crashes` for process-restart coverage.

`python -m tests.recovery.raw_receiving` owns an isolated initialized service and remote S3 fixture to verify pre-upload raw reuse, bounded request workspace, protocol failures, corruption and crash cleanup. Run it with the `source_quarantine` fixture variables and a disposable primary database.

`python -m tests.recovery.raw_uploads` owns the stopped source-quarantine service and S3 fixture. Give node cache at least 64 MiB, including 32 MiB for uploads. On each product check GET/HEAD/Range after early ACK, PUT/Copy/multipart, disabling cache/restart, quota fallback, condition/checksum failures, maintenance flush bounds, crash after final upload and corruption of the only cached copy.

`python -m tests.recovery.cached_encoding` uses the same service/S3 fixture with at least 8 MiB upload cache. Verify durable ACK before final encoding, no early nonce use, reads/dedup, restart, settings changes during encoding, retention of old keys, final direct-pack file counts, independent compressed chunks and full-cache reject/fallback. For a running two-data fixture set `MOKYU_TEST_PEER_ENDPOINT` and `MOKYU_TEST_SOURCE_FAULT_DIRS`; single-container tests own the service. Run each database product separately.

`python -m tests.recovery.background_cdc` checks early raw ACK, frozen settings, direct background packing, healthy reuse, concurrent duplicate content, active readers, overwrite/delete, empty bodies, kill after candidate upload, bad sources and successful repair/retry, explicit cache flush and multipart. Run on each product; `MOKYU_TEST_CDC_LOCAL=1` selects local storage. For two data nodes use the peer/fault variables. Contention requires `upload_idle_timeout="10s"`; the single-container fixture sets it and restarts. Set it before starting cluster nodes. Fault points are for isolated builds only.

`python -m tests.recovery.credential_activity` uses a stopped isolated service and the source-quarantine fixture variables to verify signed GET/HEAD while credential activity writes are paused, bounded timeout and retry, five-minute coalescing, invalid signature isolation, and restart loss of optional statistics. Run against each supported database.

`python -m tests.recovery.read_snapshots` uses the same stopped-service fixture and a local raw backend. It counts actual SQL by HTTP request ID for signed and anonymous GET/HEAD/Range, including Web domains, S3 path, virtual hosts and public aliases. It also checks CORS, encoded keys, empty objects, presigned URLs, failed/expired/disabled credentials, grants, conditional ACL/version races, pre-open GC pins, and current source quarantine. SQL traces remain in the isolated fault directory; run against each supported database.

`python -m tests.recovery.cors_cache` also verifies nonblocking paused fills, generation fencing, independent CORS background validation and hard expiry. It uses the same stopped-service fixture, a local backend and zero response-cache budget. It reuses the complete S3 CORS suite, then checks concurrent parsing, per-Origin/HEAD/OPTIONS behavior, CLI and both settings APIs, empty rules, domain reassignment, and bucket recreation. Run against each supported database; Rust tests additionally cover bounded allocation, retained readers, oversized documents and stale revisions.

`python -m tests.recovery.raw_responses` enables a 4 MiB response budget in the stopped-service fixture. It runs the response cache and pressure suites on raw objects, verifies one-query hot reads, signatures and current ACL, source quarantine/revisions, multipart, content changes during cache construction, and raw-to-chunks conversion, then repeats the chunk cache suite. Set `MOKYU_TEST_BACKEND` for an isolated S3 backend; run each supported database and retain the fault logs.

`python -m tests.recovery.public_read_cache` uses the stopped-service fixture and tests zero body budget metadata, zero foreground SQL for hot public HEAD/GET/Range/OPTIONS, signed and conditional isolation, local mutations, failed refresh with hard expiry, domain-edit races and raw/chunks on each supported database. The test changes another node's ACL through the isolated database to measure the explicitly configured stale-permission window.

`python -m tests.recovery.source_read_cache` uses the same stopped-service fixture with no response body budget. It verifies zero-SQL raw reads and Range with explicit source snapshots, independent source expiry, strict and signed bypass, quarantine/recheck invalidation, pre-open pins through overwrite/GC, and bounded chunk refresh failures. Run each supported database locally and set `MOKYU_TEST_BACKEND` for remote raw/chunk/pack coverage. The optional source policy in `tests.recovery.cluster_public_cache` must retain real data-node read leases on body misses.

`tests/recovery/read_integrity.py` tests optional digest policy, late cache fills, background queue/memory bounds, exact partial ranges without whole-source verification, cancellation and the boundary between bad caches and damaged backend bytes across all four products on local and remote S3. Rust content tests also cover mandatory pack and encryption authentication.

`python -m tests.recovery.received_responses` verifies hot-path PUT reuse for raw/chunks, signed and anonymous S3/Web/Range, rejected or disconnected uploads, bounded optional admission, no-store and current permissions. With `MOKYU_TEST_BACKEND`, it also verifies shared RAM allocation and independent write-quota release after drain. Uses the isolated recovery fixture and a 4MiB response cache.

`python -m tests.recovery.file_delivery` uses the stopped-service source-quarantine fixture and a 4MiB response budget. It covers local profile validation, one-query cold and zero-query hot raw reads, per-storage body-cache retirement, restoration, file size and symlink checks. With `MOKYU_TEST_PROXY_RUN` set to the application container hostname, it writes `proxy/nginx.conf`, `proxy/apache.conf` and `proxy/raw-path` beside the application config, then waits for `proxy/ready`. The orchestrator mounts only that raw directory read-only at `/srv/raw`, starts Nginx and Apache with mod_xsendfile as `<hostname>-nginx` and `<hostname>-apache`, and creates the marker. HTTP fixtures on 9100/9101 pause the handoff for GC races. Both proxy configurations come directly from the deployment document; Nginx also enables the actual optional control-cache blocks. Run in a private Docker network with isolated data and explicit resource limits.

`python -m tests.recovery.local_deployment` reproduces the documented SQLite/raw CLI initialization. Set `MOKYU_TEST_BINARY`, `MOKYU_TEST_ROOT` to an empty owned directory, and `MOKYU_TEST_ALLOW_STATE_CHANGES=isolated-only`. It owns ports 9000–9002 and starts/stops the service itself; use a fresh Linux container with 1GiB memory and UID/GID 10001 to check the documented file permissions.

`node tests/recovery/sdk_multipart.mjs /fixture.json` uses AWS SDK for JavaScript v3 and an isolated fault-injection service with `MOKYU_TEST_COMPLETE_TIMEOUT_SECONDS=12`. Install the SDK in the test environment, not the application. The private fixture contains `endpoint`, `bucket`, `access_key`, `secret_key` and the service's shared `fault_dir`; require `MOKYU_TEST_ALLOW_STATE_CHANGES=isolated-only`. It checks full PUT/GET/HEAD/Range, two-part uploads, HTTP 200 Error XML rejection/retry, five-second whitespace keepalive under an eight-second socket timeout, and successful result replay. Run raw and chunks separately, including a real reverse proxy; the script leaves its uniquely prefixed objects in the disposable bucket.

`tests/recovery/replication_locks.py` verifies bounded MySQL/MariaDB metadata transaction retries using a disposable trigger and nontransactional counter. It covers skipped bodies, ACL publication, persistent deadlocks and resumed Move; the database account must be able to create test tables and triggers.
