# RPC and cluster tests

[Test guide](../README.md) · Run commands from the repository root. Short test paths such as `fixtures/` are relative to `tests/`.

## Sessions, notifications and reads

`node_raw_checkpoints_require_current_runs_and_permits` checks raw part receipt replay, stale execution, unknown operations, format validation, disabled nodes, expired runs/permits and maintenance barriers. Supply saved receipts via `MOKYU_TEST_TRANSFER_CHECKPOINT`, database fault actions via `MOKYU_TEST_RPC_ACTIONS`, and the node identity and endpoint via `MOKYU_TEST_NODE_STATE` and `MOKYU_TEST_CONTROL_URL`.

`node_import_parts_reject_stale_runs_and_changed_seals` uses an isolated API import paused at `import-part-written`, its worker identity and control URL. `MOKYU_TEST_IMPORT_PART` supplies the current work operation, write operation, run, size and computed checksums. It checks typed errors for stale runs, changed sizes, forbidden publication conditions and out-of-phase or oversized mapping reads; rejected seals must leave the part active and unchanged.

`postgres_node_sessions_recover_across_controls_and_fence_old_runs` uses two independent pools to check credential generations, takeover, concurrent sync and heartbeat, expiry, retired boots, bounded history, rotation and disabling.

`postgres_notifications_survive_rollback_takeover_and_membership_changes` uses fresh PostgreSQL to check rollback, coalescing in one transaction, ACL changes with identical ETags, expired claims, duplicate and cross-generation acknowledgments, activation racing publication in either order, LISTEN disconnects and expiry. Single-container operations must not emit cluster events. Unit tests cover late fills, merging candidates and single refresh completion.

`postgres_refresh_reads_batch_public_metadata_and_fence_callers` refreshes 32 public entries on isolated PostgreSQL. It checks coalescing across calls, shared materials, body-source proofs, route aliases, per-item denial and run isolation without new read leases or storage permits. `postgres_node_reads_close_dependencies_bound_windows_and_protect_sources` covers regular reads assembled from the same sources.

`rpc::client::transport_tests::rotation::node_rpc_survives_connection_rotation` sets the isolated TLS proxy's `keepalive_requests` to 8 and runs 100 batches of eight concurrent SyncNode calls. Normal connection rotation must not reach callers as a failure. Unit tests distinguish GOAWAY from protocol errors, RST_STREAM and application errors.

Give each data, worker or node its own configuration and pre-created identity. Supply the observer's PostgreSQL connection separately; node configurations contain no database credentials. `tests.control.cluster_runtime_history` uses `MOKYU_TEST_DATA_ENDPOINTS`, a JSON array of two public read endpoints, to check actual requests against node and cluster history.

`postgres_node_reads_close_dependencies_bound_windows_and_protect_sources` covers read dependencies, material reuse, ranges past the initial window, two-window backpressure, resource expiry, node isolation and GC protection for chunk, pack, raw and pending sources during mapping changes.

`rpc::client::transport_tests::reads::node_read_plans_reuse_materials_fetch_s3_and_survive_lost_replies` uses two controls, TLS and dedicated S3 storage. `MOKYU_TEST_READ_FIXTURE` points to JSON containing the bucket, read credentials, expected body path and worker identity path. Implement `change-read-profile`, `lose-read`, `resume-read` and `assert-no-reads` in the harness; drop the response at `node-read-opened`. Check direct decryption after one RPC, material/body reuse, paged reads and replay across controls.

`rpc::client::transport_tests::reads::node_read_resources_renew_reconnect_and_release_automatically` requires `record-read-expiry`, `assert-read-renewed` and `assert-live-read` to compare expiry and live resources. Check cold/hot HEAD, two-window prefetch, full/range reads, renewal, control failure and final release. Optional `body_cases` entries (bucket, key, access_key, body_path, source) exercise empty, mixed chunk/pack and raw objects. Pause `node-read-decode` in `MOKYU_TEST_FAULT_DIR`; cancelling a reader must retain its protection until blocking work stops. Unit tests cover batch caps, late confirmation, budgets, revisions, deployment identity, bounds, sliced-body charging, raw digests and remote ETags.

`rpc::client::transport_tests::reads::http::node_http_reads_use_one_rpc_and_verify_signatures` starts S3/Web on isolated ports 19100/19101 and writes `http-ports.json`. Implement `http-signed`, `http-sources`, `http-public`, `http-proxy`, `http-compression-busy`, `http-rejected`, `http-pending`, `http-reconnected` and `http-fenced` with real SDK, HTTP/1.1, h2c and TLS requests. Proxy via h2c without changing Host or the signed path. Check negotiated protocol, one OpenRead, signature rejection priority, body-free HEAD/conditional requests, compression fallback, source release and control recovery. Revoke the run during `http-compression-finish`. Include empty, pack and raw objects, escaped paths, public host with port, CORS, index and error pages. Mark only the fixture's pending raw source as owned by another node; check waiting, readiness and bucket revision changes. This tests the adapter; role and CDN tests are separate.

Enable CORS caching in the HTTP fixture. `http-cors-disabled` and `http-cors-update` exercise HEAD/OPTIONS through each of the three paths after switch and revision changes, with the policy supplied by the same OpenRead. Rust checks shared hits and budgets; unit tests cover cross-bucket reuse, late revisions and background queue completion.

`rpc::client::transport_tests::reads::http::node_http_cache_validates_versions_and_recovers` enables a 16 MiB body cache. `l1-*` actions use separate public objects for all three HTTP paths: hits, ranges, encoding from identity, busy-encoder reuse, denied ACLs, policy changes, replacement and control recovery. Assert actual backend GETs, hits and budgets. Pause `http-compression-finish` to exclude cancelled candidates and `response-cache-body` to fence cached responses without a read lease.

`rpc::client::transport_tests::reads::http::node_http_file_cache_recovers_and_falls_back` disables body L1 and sets a 16 MiB/128-entry file cache. `l2-*` actions check hot reads and ranges over HTTP/1.1, h2c and TLS, rebuilding corrupt entries, pack reuse, disabling/re-enabling, directory recovery and control failure. `l2-raw-*` actions cover coalesced cold downloads, hot raw ranges, corruption and restart. Cancel at `node-raw-before-verify` before verification: nothing is published and the reservation is released. Revoke a run during blocking `node-cache-decode`; the response must abort promptly. Unit tests cover pins, unlink failures and actual disk charges.

`rpc::client::transport_tests::reads::checks::node_checks_verify_bodies_and_report_owned_sources` requires the read fixture, a dedicated worker and actions `checks-queued`, `checks-run-healthy`, `checks-background`, `checks-range-verified`, `checks-corrupt-raw`, `checks-quarantined-raw`, `checks-corrupt-chunk` and `checks-quarantined-chunk`. Use task IDs from `check-tasks.json`. Check deduplication of batch reports, read/window/role fences, reconnect replay, healthy sources, background raw digests, range rechecks and durable review of corrupt encrypted chunks. Corrupt only this fixture's backend objects.

`rpc::client::transport_tests::node_rpc_balances_tls_origins_and_recovers_sessions` needs two running controls, a TLS origin for each, and an isolated action runner. Set `MOKYU_TEST_NODE_STATE`, `MOKYU_TEST_CONTROL_URL`, `MOKYU_TEST_RPC_ACTIONS` and `SSL_CERT_FILE` for the test CA. A temporary local UDP DNS server publishes changing A records for `127.0.0.2/3`; `127.0.0.4` serves a certificate for the wrong host. Watch the actions directory for `change-settings`, `stop-first`, `start-first`, `lose-welcome`, `resume-welcome`, `rotate-node` and `disable-node`; write `ok` to the matching `.done` file after completion. Drop Welcome at `node-session-opened`. Only the DNS grace clock is simulated; this exercises real DNS/TLS/gRPC, not a CDN or intercontinental path.

`rpc::client::transport_tests::node_runtime_recovers_without_database_or_resurrecting_old_work` uses the same fixture without database settings on the node. Add `enable-maintenance`, `disable-maintenance` and `expire-run` (expire only this node's run). Check lost Welcome, DNS changes, origin failure, settings, maintenance, expiry, drain/reconnect, credential rotation and invalidation of cancelled handles. Exercise full data/worker processes separately.

Role contracts cover `node` reads/writes and shared work, pure `data` rejecting shared tasks, and prevention of one data/worker/node claiming another's local uploads even after expiry. PostgreSQL entry points: `node_reads`, `node_writes`, `node_raw` and `node_multipart`.

NodeSession notification fault points are `notification-wake` (pause a consumed PostgreSQL wake while durable scanning continues), `notifications-claimed` (pause dispatch after committing claims), and `notification-receipt` (pause before persisting an application receipt). Arm only the isolated controls under test; the runner owns process termination, restart and removal of every marker. A retired target generation is not a successful delivery. Verify the replacement session and its first read separately.

## Real node and replica fixtures

`python -m tests.recovery.cluster_shutdown` uses the two-data `cluster_cache` fixture. Handle `stop-peer` and `start-peer` and acknowledge via `.done`. Check continued heartbeat during shutdown, draining only the local node's raw/chunks/native multipart, remote reads of final sources and shared pending writes only for CDC tails.

`python -m tests.recovery.key_replacement_cluster` needs two data nodes with PostgreSQL/S3, `MOKYU_TEST_PEER_ENDPOINT` and both nodes' `MOKYU_TEST_SOURCE_FAULT_DIRS`. Check cross-node use of a new key, retention of an in-flight old key, periodic refresh after blocked notification and offline restart. Under the config directory handle `replacement-control/stop-peer` or `start-peer` by stopping/starting the second data node and writing `.done`. `key-capacity.spec.ts` and `key-replacement.spec.ts` check all locales, themes, widths 320–1440 px, warning thresholds, keyboard hints and preview restoration.

- `recovery/cluster_identities.py`: two real data nodes write encrypted chunks concurrently. Check unique nonces, draining each local write cache, cross-node reads and identical UUIDs, bodies and ranges after pack/unpack. Use dedicated PostgreSQL and S3, the `source_quarantine` fixture and `MOKYU_TEST_PEER_ENDPOINT`.

- `recovery/cluster_policy.py`: two real data nodes share S3 via the `raw_cluster.py` fixture. Check per-backend idle periods, cross-node renewed writes and completion under the longer policy; trigger reclamation via the maintenance endpoint.

- `recovery/remote_multipart.py`: use the two-data `raw_cluster.py` fixture and `replacement-control` kill/start markers. Cover native MPU sparse/out-of-order writes, local-only pending data, early ACK/restart, late replacement of the same part, kill after upstream completion, full-cache reject/fallback, abort, empty body, profile updates, maintenance drain, low space and idle cleanup.
- `recovery/raw_cluster.py`: real two-node remote raw multipart, cross-node Complete/dedup/reads, slow validation renewal and GC. Set `MOKYU_TEST_PEER_ENDPOINT`, configure `read_idle_timeout=30s` and point faults at the first data node. `--cache` adds raw file-cache and slow-hit renewal checks: allow at least 32 MiB per node and set `MOKYU_TEST_CACHE_DIRS` to both comma-separated data/cache/raw paths.

- `recovery/cluster_runtime.py`: start actual PostgreSQL cluster roles and exercise the node lifecycle.
- `recovery/cluster_scheduler.py`: two data nodes and one independent worker; upload ownership, notification disconnect fallback, pause isolation and bounded idle database work.
- `recovery/maintenance_state.py`: two controls, two data nodes and one worker. Follow the file's fixture instructions. Run `enable`, restart a data node, then `resume`, `failure`, `race` and `drain`. `failure` temporarily locks the dedicated database table, cancels node status queries and releases it. At the `drain` stop marker send SIGTERM to the first control; late admin calls on retained connections must not reopen writes. Restart it afterwards.
- `recovery/cluster_cache.py`: two data nodes; check local raw/chunk ACKs, ownership, restart, handoff to read cache, bounded wait and CORS for signed/anonymous/Web GET, ACL checks, cluster maintenance drain and multipart completion using final chunks/shared CDC tails. Use the `raw_cluster.py` fixture, `MOKYU_TEST_SOURCE_FAULT_DIRS` as comma-separated data-node fault directories and at least 256 MiB cache per node. Watch `replacement-control/` for `kill-primary`/`start-primary`; acknowledge completion with `.done`.

- `recovery/read_leases.py`: two data nodes, time-based renewal, lightweight metadata reads and expired lease rejection. Configure read idle timeout `30s`. Run the client outside the constrained service container and reserve at least 1 GiB.
- `recovery/read_replicas.py`: an isolated PostgreSQL primary and actual hot standby with its own read-only user. Supply replica admin DSN file `MOKYU_TEST_REPLICA_DATABASE_FILE`, `MOKYU_TEST_REPLICA_USER`, the data node's `MOKYU_TEST_STATUS_URL` and fault directory. Set read idle timeout `30s`, reader concurrency at least four, replica pool two. The test pauses replay and changes privileges. It checks public pagination, exclusion of signed requests, wrong privilege/identity, blocked DDL replay, connection/time budgets, expired primary leases and deletion during streaming.

`postgres_chunk_claims_release_connections_and_fence_stale_writers` takes a new PostgreSQL database and `--ignored`. It covers a small pool plus LISTEN, short claim locks, expired lease/token, atomic preparation rollback, unknown source records and cancellation during SQL waits. `python -m tests.recovery.claim_pool` uses the two-data source-repair fixture and `MOKYU_TEST_SECOND_DATA` with both data pools set to four. Two paused uploads must leave query capacity; test same-content exclusion, independent writes, full readback and expired-writer rejection before allocation/upload/completion. `tests.recovery.repair_cluster` covers repair races and privilege revocation; leave GC enabled.

`python -m tests.recovery.cluster_scheduler` also requires an independent worker, `instance.cpu_jobs = 1` on all three execution nodes, nonzero read/upload disk cache budgets and the two-data `MOKYU_TEST_SECOND_DATA`/`MOKYU_TEST_SOURCE_FAULT_DIRS` fixture. Pause one local upload while another advances. Disconnect only the fixture's task LISTEN session. Check recovery, stale executor rejection, full cross-node readback, and bounded idle transactions over six seconds.

Run `postgres_source_validation_allows_references` against a fresh PostgreSQL `MOKYU_TEST_DATABASE_URL_FILE` with `--ignored`. Race active references, quarantine and pack remapping: the physical lock must survive a switch from an independent chunk to a pack while waiting. Check empty/fragment sources and generic/custom plans with 4097 chunks.

- `python -m tests.recovery.raw_processing_cluster` uses `raw_cluster`'s two real data nodes/shared S3 with both fault directories in `MOKYU_TEST_SOURCE_FAULT_DIRS`. Check shared reader protection, takeover after lease expiry, disabled nodes, reclaim without a lease and no repeat switch by a late executor. Reserve two LISTEN connections; with one query connection and a waiting row lock, renewal must not prevent transaction progress.

`python -m tests.recovery.cluster_responses` uses the two-data-node `cluster_cache` fixture with `response_cache_size = "4MiB"` on both data nodes. It verifies independent raw identity/compressed caches, signed and public S3/Web reuse, CORS, HEAD, Range, current ACL and credentials, overwrites and deletion.

`python -m tests.recovery.cluster_public_cache` uses the same two-data-node fixture with two controls to verify per-node metadata/body reuse, confirmed peer invalidation, current signed credential revocation, overwrite/delete, source health and read-integrity changes. Set `MOKYU_TEST_CONTROL_FAULT_DIRS` to both comma-separated control fault directories. The test first waits for the peer application receipt, then deliberately pauses notification dispatch to verify the configured hard expiry independently.

`python -m tests.recovery.cluster_cors_cache` requires two isolated API data nodes, PostgreSQL controls and the shared S3 fixture. It covers forced CORS caching with public snapshots, independent CORS-only confirmation and peer convergence. Set `MOKYU_TEST_CORS_RESTART_SIGNALS` when the harness can restart the peer after `restart-peer` appears to verify deployment-wide limits with independent per-node activation.
