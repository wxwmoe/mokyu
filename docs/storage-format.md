# 存储格式

数据库保存对象路径、权限和物理引用；storage 保存原始文件、区块和区块包。storage 文件本身不能单独重建对象索引。格式编号独立于数据库 schema 和程序版本，新增格式只追加编号，不复用旧编号。

## 原始文件

单容器的 `write_durability=buffered` 允许本地 chunks/raw 及 S3 写缓存文件完整写入后省略请求期的文件与发布目录同步。来源记录保留缓冲状态，由后台同步后标记持久；`cache status` 的 `buffered_files` 和 `buffered_chunks` 分别提供 raw 与区块待同步条目、字节与最早创建时间，`cache flush` 和正常退出也包含这些来源。可靠写入、复制和迁移引用缓冲来源前先同步。重启先核验未同步文件的长度和摘要，缺失或损坏的来源被隔离，运行中临时 I/O 故障保留重试，启动核验无法完成则终止启动并保留来源；这不能保证断电后最近写入不丢失，SQLite 元数据同步策略仍独立生效。

单容器 S3 写缓存可选 `write_durability=volatile`，在 `instance.write_memory_size` 内保留 raw 或完整区块，以相同物理 UUID 供读取和最终上传。RAM 中不会创建替代缓存文件或缓存 UUID；额度不足改用 buffered 文件并沿用满额策略。来源同时保存本次进程 boot_id，强引用和排空先转成持久文件或完成最终上传再解除标记。进程重启后尚未落盘的 RAM 来源进入隔离，保留对象映射供诊断和重传恢复，不回退旧版本；已发布最终 S3 的来源不受影响。`cache status` 的 `write_memory` 显示容量与在用字节，`buffered_files` / `buffered_chunks` 的 `volatile` 显示待处理 RAM 来源数；已丢失来源保留在来源隔离列表，并在启动日志报告。

local 和 S3 storage 均可关闭 profile 的 `cdc_enabled`，新写入以原始字节保存，不生成区块、存储压缩、加密或区块包。普通 PUT 和完成后的 Multipart 均对应一个不可变 UUID 文件；空对象也有完整文件和来源记录。Multipart 复用既有暂存目录、分片校验和清理，UploadPart 跳过 CDC，raw 命名空间不保存独立的客户端分片。

单容器普通 raw GET、HEAD 和 Range 将桶路由、对象、来源状态及 S3 读取授权合并到一次数据库查询，Web 公共读与匿名 S3 共用此路径。带条件的 GET 保留元数据判断后的权限与版本复查；群集继续使用数据库读取租约。请求内的快照和文件引用保护不代替签名、文件长度与摘要校验。

单容器 raw 的 Multipart 向本地候选文件追加数据，在数据库记录分片范围；文件随实际到达数据增长，不按声明的总大小预分配。Complete 在本地后端或 S3 写缓存中组装时，先封存候选文件，再按客户端选中的分片清单生成完整文件：连续完整布局直接复用同一文件系统上的 inode，其他布局在启动后台探测确认支持后使用 Linux reflink，未完成探测、不支持、跨文件系统或范围未对齐时使用有界复制。探测结果按文件系统组合保留到进程退出，新增或修改本地存储路径时也会后台探测；探测失败不阻止启动，重启后重新探测。布局元数据超过内存上限时沿用流式组装，可能同时保留原暂存与完整目标文件，需预留相应磁盘空间。各条路径仍核对范围、分片和完整正文的校验和，并等待文件同步与元数据发布；被替换、未选中或失败请求留下的字节不会混入最终对象。封存后的上传候选不再追加，失败后的新分片使用新的候选文件。单容器 S3 未开启写缓存时从已有分片流式上传。

群集 raw Multipart 复用节点本地候选文件与偏移映射，分片按原编号流式上传到最终后端的原生 S3 Multipart；共享 staging 不保存 raw 数据。开启写缓存时，本地文件确认和分片代次提交后即可响应；关闭或满额回退时等待该分片的远端确认。Complete 等待所选分片，使用固定的远端 ETag 清单完成上传，再有界读取最终文件核对分片和完整摘要后发布；同编号迟到覆盖导致 InvalidPart 时重传所选代次。原本地分片保留至完成或中止，以便安全重传，远端已确认的分片可由其他节点完成合并。

复制可领先持久确认两个有界批次；确认目标范围和目录后，事务更新分片映射，再释放旧候选中无引用的范围。最后一批回收交给后台 GC，待回收标记和范围映射随数据库保存，重启后继续处理；Complete 仍等待最终文件、校验和元数据发布。其他硬链接存在或文件系统不支持打洞时保留旧范围，空间不足会拒绝继续复制，已有分片仍可重试。

```text
<storage.prefix>/raw/<UUID 后两位>/<32 位小写 UUID>
<storage.prefix>/raw/<UUID 后两位>/<32 位小写 UUID>.partial
```

raw 与区块、区块包共用根目录 `meta.json` 的命名空间身份，不另建 raw 标记。本地与 S3 使用相同的最终相对路径和原始文件字节。物理路径只使用服务端 UUID，不使用桶名或对象键。`.partial` 用于本地接收和可恢复的 Multipart 组装；已确认范围可能仍被上传引用，不能手动删除，引用释放后由 GC 清理。远端使用有界 S3 multipart 传输，并记录 upload ID 供失败清理。单容器 Multipart 完成、Copy 和迁移按总长规划远端分片，从现有来源流式读取并校验，重试重新读取相同范围，不将整个分片放入内存；分片最多 10,000 个、每片不超过 5 GiB，仍受后端自身对象大小和请求超时限制。建议为远端配置 `AbortIncompleteMultipartUpload` 生命周期规则，清理创建请求已成功但响应丢失、尚无法登记 ID 的上传。

`deduplication_enabled` 默认 false。开启后按 `storage_id + 完整正文 BLAKE3 + 长度` 共享健康的最终来源，不使用 Multipart ETag 作为内容身份；不同分片边界不影响去重。不使用写缓存时，`write_processing=inline` 在发布前登记或切换引用，远端 S3 在最终上传前查重；`background` 先可靠发布独立文件和待处理记录，再计算摘要并事务切换，重启继续。后台切换保留对象版本、ETag、权限和时间，等已有读者释放保护后才执行；持续长读可能推迟去重。多余副本由 GC 回收。群集原生 Multipart 的分片先上传，完整摘要在最终文件校验时计算，随后共享健康来源并回收多余候选；该路径不能省去重复分片的远端传输。关闭去重仅影响新写入，已有共享文件和待处理工作保持原有合同。

未启用写缓存时，远端即时去重的 PUT 使用有界缓冲，大对象按实际接收量写入 `<data_path>/raw/<后两位>/<UUID>.partial`，受节点缓存总额、后端 `cache_soft_limit` 和磁盘余量保护。空间不足返回 `503 SlowDown`，不发布部分对象；取消或重启后清理未确认请求的临时文件。Multipart、Copy 和迁移直接重放已有来源，避免再暂存整文件。命中健康来源时不上传最终文件，未命中时仍等待最终 S3 确认及对象发布；并发首次写入可能各自生成候选，随后合并引用。

S3 raw 开启 `upload_cache` 后，在 `<data_path>/raw/<后两位>/<UUID>` 同步完整文件并提交对象映射即可响应；UUID 与最终后端文件相同。后台先复核并查重，只有未命中才上传最终 S3；inline 优先推进，background 按维护队列配额推进。上传配额不足时，`upload_cache_overflow=fallback` 回退同步查重和上传，请求全程等待；`reject` 返回 `503 SlowDown`，不发布本次对象。群集复用该流程，待上传文件属于接收节点，其他节点不能领取。

待上传记录按物理来源保存，原对象删除但 Copy 仍引用时继续排空。文件由 pin 保护，关闭缓存、缩小额度或重启均不会淘汰唯一副本；最终上传或引用切换后，原文件可作为普通读缓存回收，无需另行复制。单容器 S3 Multipart 的组装检查点位于节点 raw 缓存目录，其分片引用释放前仍受保护；已发布文件与检查点共用 inode 时只计一份缓存长度。启动发现唯一副本缺失或长度不符会中止恢复，不静默丢弃记录。

群集 raw 和 chunks 的写缓存保存在所属节点的 `instance.data_path`，上传完成后释放写入额度并保留普通读缓存，仍受现有 reader/Multipart pin 和淘汰规则管理。原节点携同数据目录重启可继续上传；其他节点不会接管无法访问的本地文件，节点永久丢失不由共享暂存恢复。跨节点 GET 在需要待上传来源时最多等待约 3 秒，超时返回 `503 SlowDown`、`Retry-After: 60` 和 `Cache-Control: no-store`；HEAD 和列表不等待正文，完整内存响应缓存命中也不等待。

`mokyu cli cache status` 的 `raw_processing` 显示可选去重工作，`raw_uploads` 显示必须排空的来源及群集原生 Multipart 待传分片，两者均提供 `pending`、`bytes` 和 `failed`。`cache flush` 支持维护模式，只等待任务创建前的待上传来源与缓冲文件。后台失败保留来源与重试记录，不将未通过长度和摘要复核的来源登记为共享文件，也不保证整体处理吞吐提升。

接收前先登记来源。默认持久确认时，本地在目标目录内独占创建 `.partial`，完整协议与摘要验证后同步文件、发布不可变名称并同步父目录，再提交逻辑映射；远端在完整上传确认后提交映射。覆盖创建新来源；失败不替换旧对象，未发布文件由来源记录和正常 GC 回收。原始来源保存 16 字节 MD5 摘要，普通读取先检查完整来源的长度和摘要；Range 按对象映射读取。

关闭或重新开启 CDC 只影响新写入，已有原始文件与区块格式并存。原始文件进入既有巡检、隔离、完整复检和用量统计；它们没有区块重传去重恢复，可恢复原位置的正确字节后复检，或重新上传对象。`storage rewrite` 处理区块与区块包，不隐式转换原始对象。

同一 storage 可在单容器维护状态下搬迁整个命名空间并修改连接类型；保留数据库、部署密钥、storage ID 和根 `meta.json`，同时复制历史 raw、区块与区块包。先完成或中止 Multipart、排空待写来源及后台任务，停止对原命名空间的写入；复制期间不能让两边独立写入。修改连接会核对根标记并更新 raw 来源介质，成功后须重启，旧连接不再提供数据服务。标记匹配不证明所有文件已迁齐，恢复入口前应核对完整性。

也可创建新的目标 storage 和桶，使用管理面板的跨存储复制或移动；任务按目标 CDC、去重、压缩与加密策略接收逻辑内容。该方式不修改原 storage 的连接，允许分批迁移。桶绑定的 storage ID 不变；这两种方式都不是跨数据库迁移。原始对象 Copy 先接收完整内容，再按目标去重设置选择来源；旧读取持有的文件在引用释放和保留期结束前不会回收。

本地 raw 的完整匿名 GET 可按 storage profile 交给受信代理。代理只读挂载原始文件，配置前缀对应 `<storage path>/<prefix>/raw/`，后接 `<后两位>/<UUID>`，不得直接导出对象 key 或整个 data 目录。代理打开前发生回收时，必须回退 Mokyu 重新读取逻辑对象；配置与限制见[代理文件交付](local-nginx-deployment.md)。

## 后台分块

`cdc_enabled=true` 与 `write_processing=background` 同时启用时，普通 PUT 先接收为不可变 raw。后台任务保存接受时的压缩、组包及密钥设置，分批读取原始文件、计算 CDC/BLAKE3 并引用健康旧块；未命中的连续区块在有界内存中直接编码为最终区块包，不先生成独立区块文件。本地 storage 或关闭组包时直接生成独立编码。Multipart 沿用现有流式分块流程，仅未闭合的尾块需要暂存。

新映射属于不可见的候选 stream。完整正文摘要校验通过、所有来源已可靠保存且旧读者释放保护后，事务再次检查执行令牌、对象版本和来源健康，原子切换原 stream 的表示并递增 `payload_revision`；对象版本、ETag、权限、元数据与时间不变。失败保留原始表示和错误诊断，重启或重试不会发布半成品，覆盖或删除后的旧任务不能重新发布对象。持续长读可能推迟切换。

转换前的 raw 不使用存储压缩或区块加密。S3 写缓存满且选择 `fallback` 时，在当前请求内从临时文件分块、查重并上传最终区块，完成后才响应，不上传中间 raw；选择 `reject` 则返回 503，保留原对象。

开启 S3 写缓存时，后台从节点本地 raw 转换并直接上传最终 chunks/packs；共享 staging 不保存原始文件。手动刷新写缓存会先持久化尚未转换的 raw，CDC 暂停不阻塞排空。关闭写缓存时先将原始文件可靠写入最终后端再响应，后台转换会增加一次读取和后续输出成本。切换后旧 raw 仍按引用与 GC 规则回收；其他对象若仍引用它，继续保留并完成其必要上传。

## 分块和去重

- 使用 FastCDC v2020，最小 256 KiB、目标 1 MiB、最大 4 MiB；不足最小值的非空完整对象使用一个区块，空对象没有区块。
- 逻辑区块按 `storage_id + hash + raw_size` 去重，`hash` 是原始明文的 32 字节 BLAKE3。同一 storage 的不同桶共享去重，不同 storage 不共享。
- 每个物理来源独立决定压缩和加密。compression profile 支持 `never`、`always`、`sample`；区块包压缩独立记录。新策略不会隐式重写已有来源。
- 加密支持 `none`、AES-256-GCM 和 ChaCha20-Poly1305；认证标签附在密文末尾。block key 由数据库管理，key 算法创建后不可更改。

逻辑区块的持久 UUID 在同一 storage 的重写和重新打包时保持不变。PostgreSQL 使用数据库生成的 UUIDv7 主键；MySQL/MariaDB 和 SQLite 保留整数主键，`chunks.uuid` 保存 Mokyu 生成的 UUIDv7。物理区块编码与区块包各有独立 UUID；重写创建新的物理身份，旧来源在新来源提交后按 GC 宽限回收。

## 物理编码和完整性

每个 ready 独立来源保存物理 UUID、`standalone_size`、`standalone_compressed`、`encryption_algorithm`、`block_key_id`、`nonce_id`、nonce 和 `encoding_fingerprint`；区块包保存对应的 `pack_fingerprint`。fingerprint 绑定 key、算法、压缩和 storage profile，`storage rewrite` 用它判断是否需要处理。

区块格式为 2，AAD 标记为 `MOKYU\0\0\x03`，绑定持久逻辑 UUID、物理 UUID、明文哈希、原始长度、编码长度、压缩标志、算法和 block key UUID。数据库整数主键不进入密文格式。读取顺序固定为认证、解密、有界解压、长度检查和 BLAKE3 检查；任何元数据或载荷不匹配都报告完整性错误。

nonce 为 12 字节：前 4 字节编码来源类型和 UTC 日期，后 8 字节为独立的正整数 `nonce_id`。加密的物理区块编码和区块包分别使用类型标记 0 和 1；未加密来源的 `nonce_id`、nonce 和 `block_key_id` 均为空。逻辑区块、pack 成员和 raw 不单独分配 nonce。

`nonce_counters` 按 block key 和类型标记保存已预留高水位。进程在实际加密前按近期使用速率领取 64–65536 个编号，大小为 64 的倍数，数据库提交成功后才开始使用。重启、失败或取消留下的余量不回收；启动、读取、无加密写入和直接去重命中不领取范围。可用余量不足 64 时拒绝新预留，需要创建新的实际 block key 并切换关联存储；已有有效范围仍可用完。同一密钥材料不能以其他名称重新开始计数。

数据库恢复、计数回滚或独立克隆后，恢复写入前必须更换新的实际 block key，并保留历史 key 读取存量来源。当前格式密文使用记录中的 nonce 解密。

## 存储布局

```text
<storage.prefix>/meta.json
<storage.prefix>/<UUID 后两位>/<32 位小写 UUID>
<storage.prefix>/packs/<UUID 后两位>/<32 位小写 UUID>
```

`meta.json` 的 `format_version` 为 4，chunk/pack layout 分别为 `uuid-suffix2`、`uuid-suffix2-pack`，按 UUID 最后两位十六进制字符分目录，区块包位于 `packs/` 下。它包含 `deployment_id`、`storage_id`、chunk/pack layout、创建时间和版本诊断字段。创建 storage 时只允许在目标命名空间为空的情况下用条件写入初始化；编辑已有 storage 时必须读取并匹配完整 meta，缺失或不匹配会拒绝保存。修改 prefix 不会自动搬迁载荷。

独立区块直接使用 UUID 分片路径。sweep 同时识别此前文档中的 `chunks/<分片>/<UUID>` 路径；任何仍被物理索引记录的 UUID 都受到保护。

群集只有尚未闭合的 CDC Multipart 尾块使用共享 staging storage 的保留前缀：

```text
<storage.prefix>/__mokyu/multipart/fragment/<UUID>
```

暂存对象不参与区块去重、普通目录、usage、rewrite 或 GC；由 `staging_objects` 和 runtime 的 staging 字节上限管理。其他载荷均使用有界内存、节点本地缓存或最终后端；单容器和群集复用本地 Multipart、raw/chunks 写缓存及回收机制。

## 分片上传与发布

UploadPart 验证长度和校验和后，事务替换对应分片代次。Complete 在事务内冻结所选分片代次和清单摘要，保存执行 token 与租约；发布时核对同一 token、清单及有效租约。等待不持有数据库事务或连接，客户端重试不能并行重复执行同一清单。完成结果持久化后释放分片引用，失败保留仍可重试的来源。

HTTP 连接关闭或保活截止只结束等待，后台继续处理。进程中断后，客户端使用相同清单重试可恢复，旧执行者不能重置或发布新执行。响应和重试规则见 [S3 兼容性](s3-compatibility.md)。

## 区块包

区块包只收集同一 storage、完整且连续的 CDC 区块，成员至少两个，原始成员总长受 profile 的 `pack_max_size` 限制。包整体可压缩并按包的 key 加密，成员索引和未压缩载荷摘要写入包头及数据库。包头及 AAD 标记为 `MOKYU\0\0\x04`；包头由 8 字节标记、4 字节成员数和每成员 52 字节索引组成，索引依次为 16 字节逻辑区块 UUID、32 字节 BLAKE3 和 4 字节原始长度，整数按大端保存。随后顺序保存成员原始正文。

local storage 不创建新区块包；已有包保持可读，显式 `storage unpack` 才会拆包。S3 storage 可由普通 pack 调度器处理符合条件的存量独立区块，也可由显式 `storage rewrite` 按当前 profile 全量重写。保存 storage 表单或载入预设都不会自动启动这些任务。

S3 写缓存接收新块时先持久保存已校验的原始字节，不提前生成独立压缩或加密编码。后台先收集合适的新块，再直接生成最终区块包；单块、关闭组包或不满足布局条件时生成独立编码。加密序号仅在实际编码时领取。原始待上传块可能比压缩缓存占用更多空间，仍受同一写缓存配额及满额策略约束；开启最终加密不表示节点暂存目录中的内容也是密文。 新块的压缩、打包和密钥设置随上传记录保存，修改后端设置只影响随后接受的新块；后台重启恢复沿用已保存的设置，不同设置不合并成同一个包。已有健康来源仍可直接复用，维护性重写使用当前设置。

## 本地目录和缓存

各节点的本地目录由 `instance.data_path` 指定：

```text
<data_path>/chunks/<后两位>/<UUID>.zst
<data_path>/chunks/<后两位>/<UUID>.raw
<data_path>/raw/<后两位>/<UUID>
<data_path>/read-cache/chunks/<后两位>/<UUID>.raw
<data_path>/multipart/<fragment or candidate UUID>
<data_path>/node.json
```

Multipart 暂存配额按文件实际分配的磁盘块计量，稀疏空洞和已回收区间不继续占用配额；不支持物理块查询的平台保守按文件长度计量。同一文件系统上的暂存、缓存和目标后端写入共享进行中的空间预留，已落盘的部分由文件系统可用空间反映。

API 节点的可丢弃区块读缓存位于 `read-cache/chunks`，与唯一待上传来源分开。独立区块使用物理来源 UUID，Pack 解包成员使用逻辑区块 UUID；写入已核验的明文 `.raw`，也能读取 `.zst` 缓存。重新加载时恢复合格文件并清理该缓存目录中的未完成填充，不扫描或回收唯一来源目录。

本地 storage 的载荷直接从本地后端读取，不进入磁盘读写缓存；为性能可关闭本地 storage 的压缩和加密。S3 storage 才使用 profile cache，损坏缓存可回源重建。待上传的唯一副本受 pin 保护，不能按普通缓存淘汰。

Linux 下，Mokyu 启动时设置 umask 为 `0022`；新建目录使用 `0755`，载荷、缓存和 Multipart 暂存等普通文件使用 `0644`。SQLite 数据库及伴随文件、节点凭据和含密钥的配置属于敏感文件，使用 `0600`；敏感临时副本也须从创建时限制权限。用户提供的配置文件需由部署者设置权限。移动、硬链接和发布保留已有权限，不重复检查或修改，也不自动调整已有文件。

普通文件可由能访问其路径的其他本地用户读取，包括通过 S3 设置为私有的内容；S3/Web 授权不限制直接访问文件系统。代理只读挂载需要的载荷目录，数据库、凭据和配置不共享。

区块的可选磁盘读缓存填充在有界后台任务中执行，成功 PUT 不等待读缓存填充；缓存额度不足或填充失败不影响已验证正文，响应完成不代表缓存已经写入。上传暂存仍按持久化要求落盘后确认。

远端 raw 的首次严格读取边校验边流式填充文件，完成后复用同一文件输出，避免为正文再完整下载一次；并发相同来源复用填充结果。缓存命中仍校验完整文件，Range 从同一文件句柄读取，不把大对象作为区块或整文件 Bytes 放入内存。raw 与 chunks 共用节点缓存额度、索引和淘汰保护；独立区块缓存复用后端物理 UUID，解包缓存复用数据库批量读取的逻辑区块 UUID，不派生缓存 UUID；raw 缓存直接使用后端文件 UUID（PostgreSQL 的 `raw_sources.id`，MySQL/MariaDB/SQLite 的 `raw_sources.location_id`），UUID 均为 32 位小写无连字符格式。覆盖使用新来源 UUID，去重引用共享同一缓存文件；命名不代替权限、来源状态和长度、摘要校验。后台完整性检查和来源复检直接检查后端，损坏缓存只能回源重建，不能证明后端健康。

重启恢复完整缓存文件，清理未完成填充；正在发送的文件持有 pin，实际删除后才释放缓存占用。本地 storage 的根目录不得与 data 目录中的 raw、chunks、read-cache、multipart、thumbnails 命名空间重叠，符号链接按实际路径检查。

所有写入先持久化文件或远端对象，再提交数据库映射；local 后端在确认成功前同步文件和父目录，同步失败不会发布新映射。对象发布要求 stream 连续、来源 ready、长度和哈希全部匹配。跨 storage 的复制/移动由异步 `storage_migration` 任务完成复制、校验、权限和发布一致性；部署管理员负责两端容量、凭据、网络和供应商策略。

写入调度由每个后端的 `write_flush_interval`、`write_backlog_max_age` 和 `background_scheduling` 控制，取值及准入边界见[配置参考](configuration.md)。`cache status` 的 `write_backlog` 提供各后端最早待写时间与快照距今秒数，合并等待不改变已选择的确认级别或回收保护。
