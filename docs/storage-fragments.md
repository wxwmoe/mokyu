# 原生分片格式

本文定义 Mokyu 存储群集的分片与混合恢复载荷。storage 保存不透明字节，control 保存载荷映射和发布状态。该格式与上层[存储布局](storage-format.md)分开，不把 storage 目录当作 local 后端目录。

文件头前 5 字节是 ASCII `MOKYU`，后 3 字节是大端编号。整数使用大端编码，UUID 使用原序 16 字节。

| 编号 | 文件头 | 用途 |
| --- | --- | --- |
| `0x000009` | `MOKYU\x00\x00\x09` | 普通分片和恢复分片 |
| `0x00000a` | `MOKYU\x00\x00\x0a` | 拆片前的混合恢复载荷 |

## 分片

分片的相对路径为 `blocks/<末三位倒序>/<UUID>` 或 `recovery/<末三位倒序>/<UUID>`，UUID 文件名为 32 位小写十六进制。两类目录使用相同外层格式：320 字节头、片正文、范围校验树、80 字节完整尾部。未发布文件使用 `.part` 后缀。

| 字节偏移 | 内容 |
| --- | --- |
| 0–7 | 文件头 `0x000009` |
| 8–15 | 格式版本 u16=1、头长 u16=320、目录类别 u8、编码 u8、校验 u8=1、保留 u8=0 |
| 16–127 | 命名空间、载荷、分片、介质、群集、组合、操作，依次各一个 UUID |
| 128–175 | 布局修订、载荷修订、接管代次、覆盖起点、覆盖长度、载荷总长度，依次各一个 u64 |
| 176–191 | 本片长度 u64、文件序号 u32、条带单元字节数 u32 |
| 192–207 | 数据片数、校验片数、额外副本数、套号、片号，依次各一个 u16；保留 u16=0；校验单元 u32=65536 |
| 208–239 | 片正文的 BLAKE3 摘要 |
| 240–247 | 分片位置代次 u64，从 0 开始，修复时递增 |
| 248–287 | 保留，全部为零 |
| 288–319 | 前 288 字节的 BLAKE3 摘要 |

目录类别 0 为 `blocks`，1 为 `recovery`。编码 0 为带区，1 为 GF(2⁸) 系统 Reed–Solomon。编码 1 使用多项式 `0x11d`，Vandermonde 矩阵 `V[i,j]=i^j`，生成矩阵为 `V × inverse(V[0..K,0..K])`；前 K 行为数据片，其余为校验片。副本重复完整布局套，不改变编码矩阵。

每片文件正文最多 1 GiB；一个文件可包含多条编码条带。超大载荷按文件序号延续，覆盖起点按 K × 条带单元对齐。带区的各片只保留有效内容；有校验的编码行用零补齐，每片保存相同长度。空载荷允许零长度。未知版本、算法、非零保留位、非法身份、长度溢出和不一致的片位置均拒绝。格式定义中的布局参数不代表所有布局已开放使用。

校验叶覆盖最多 64 KiB，摘要绑定叶序号、长度和内容。叶数补齐到二次幂，填充叶使用其对应序号和空内容。内部节点绑定左右摘要，树按堆顺序存放，每节点 32 字节。叶与内部节点分别使用域 `mokyu/fragment/09/leaf` 和 `mokyu/fragment/09/node`。读取一个范围只需相关校验单元及其证明路径。

尾部为 8 字节文件头、完整文件长度 u64、树根 32 字节、提交摘要 32 字节。提交摘要以 `mokyu/fragment/09/complete` 为域，绑定头部摘要、树根和完整文件长度。空分片文件为 432 字节。普通哈希不能证明业务已经发布，必须核对 control 保存的可信回执。

## 混合恢复载荷

拆片前的恢复载荷由连续的 `0x00000a` 帧组成；磁盘上的每个恢复分片仍以 `0x000009` 开始。同一载荷的帧必须使用相同的命名空间、载荷 UUID、修订、日志及 epoch。重构后直接解析物理记录和业务记录，不嵌套 `0x000006` 日志帧。

| 字节偏移 | 内容 |
| --- | --- |
| 0–15 | 文件头、格式 u16=1、头长 u16=256、记录类型 u8、标志 u8、保留 u16=0 |
| 16–95 | 命名空间、载荷、日志、epoch、批次，依次各一个 UUID |
| 96–119 | 载荷修订、首序号、末序号，依次各一个 u64 |
| 120–151 | 前序完整帧的摘要 |
| 152–167 | 物理原长、物理存长、业务原长、业务存长，依次各一个 u32 |
| 168–199 | 随机盐 |
| 200–231 | 已存储物理分节的 BLAKE3 摘要 |
| 232–255 | 逻辑键长度 u16；其余保留为零 |

头后依次为 UTF-8 逻辑键、物理分节、业务分节、业务认证和公开完整摘要。逻辑键最多 1024 字节，位于规范的 `metadata/` 路径下；物理文件的移动不改变该认证路径。标志的低三位分别表示物理压缩、业务压缩和业务加密。记录类型沿用元数据日志的 Changes、Seal、Snapshot、Manifest、Index、Watermark、Draft、PartCommit、History，编号为 1–9；原生载荷另有 Mappings=10，普通 `0x000006` 帧拒绝该类型。

每个分节的原始和存储长度各不超过 8 MiB，每帧总封装不超过 32 MiB。完整载荷仍遵守配置的段或快照上限，至多 256 MiB；读取按帧限额处理。两部分独立选择 Zstd 压缩，仅在变小时采用；解压输出长度必须与声明一致，窗口最多 8 MiB。物理部分不加密。业务部分跟随后端设置使用 AES-256-GCM 或明文加 MAC，区块 key 仍先独立包裹。

Mappings 帧只在物理分节携带记录，业务分节为空。它与 Changes 共用全局帧序号和摘要链；逐桶业务序号另行保留。物理记录复用有界 TLV 编码，大记录可跨帧、跨文件续接，段末以 Seal 封存。原生导出立即封存当前批次，不套用 S3 最小 PUT、Multipart 分片或等待时间。

原生快照页也直接使用混合帧：Mappings 保存所引用载荷的物理映射，Snapshot 保存快照行，两者按页内序号和摘要链校验。每页有独立载荷 UUID，超过页上限时继续分块。Manifest、Index 和 Checkpoint 使用各自逻辑路径认证；可变 Index 保持载荷 UUID 并递增修订，Checkpoint 保存独立、不可变的正文。数据库在发布前保存这些确切字节，中断重试不会重新编码同一发布意图。

认证上下文绑定完整头和逻辑键，包括物理摘要、命名空间、顺序和长度。业务认证分别为 16 字节 AEAD tag 或 32 字节 MAC，末尾再保存覆盖此前全部字节的 32 字节 BLAKE3 摘要。没有业务密钥可以检查公开结构和物理分节，恢复导入仍须验证发布证据，不能将可解析的候选当作已提交恢复点。

## 控制记录

control 的 `storage_payloads` 保存不可变载荷意图与可续期写入权利，`storage_fragments` 保存确定的目标、头和回执。原始正文不写入这些表，storage 也不建立独立物理索引。

流式接收前可以用全零正文摘要表示尚未完成的计划。完整回执必须包含实际摘要、树根和提交摘要；最终文件不得把计划头当作完成头。同序号、同分片的各份副本必须具有相同正文摘要和校验树根。相同操作和内容可以重试，身份或内容不同则冲突。发布必须取得该确认档的所有必需回执，退役后不可再发布。回收必须等待读写权利退出，并由上层确认业务引用和恢复保护已经解除。

双副本的两个目标同属另一地区时，已配置地区的 data/worker 可通过 HTTP/2 `Forward` 一次上传正文，由首收 storage 并发落盘及转发给同区另一成员。两端仍返回各自签名的持久回执；转发目标地址、介质、载荷及布局均受当前群集身份约束。未配置地区、同区直写和不同目的地区分别直接发送。正文可从现有内存载荷或暂存文件重放时，转发失败后按同一意图直连重试一次；不可重放的流返回可重试失败，不提前发布。

去重命中既有载体也按群集当前确认档检查持久副本，欠镜像的 ready 载体不能使新的全部落盘请求提前成功。等待不持有发布事务；远端回收规划同时排除 control 本机仍在读取或写入的流。

物理文件状态分为不存在、待完成和完整。完整但尚未改名的 `.part` 仍是待完成候选；重试核对全部内容、同步文件并发布后才返回持久回执。Range 只返回授权范围内的正文，校验单元的相邻字节、文件头和校验树不随正文返回。

普通载荷的退役文件由现有 GC 任务分批回收。control 在签发删除授权前核对退役状态、读写租约、恢复任务和发布根保护；worker 只能请求当前清理任务列出的载荷。成功删除逐片写回数据库，断线或重启后继续处理剩余分片。尚未取得回执的文件使用绑定原计划头的丢弃授权，同时核对正式文件和 `.part`，不能仅凭文件名或年龄删除。

修复使用新分片 UUID，并将头内 `generation` 从初始 0 递增。载荷、条带位置、介质、内容摘要和校验树根保持一致，完整回执验证通过后才替换当前槽位。control 保留原回执及候选状态，未完成的候选可继续写入；旧片仍受读取与恢复点保护。同槽恢复记录按代次选择，等代次但身份不同视为冲突，不依赖目录遍历顺序。普通载荷修复的旧片在旧读租约退出、新物理映射的恢复日志确认后进入回收；进入回收的旧片禁止续期。未开启元数据日志的载荷无需等待日志发布。

## 恢复证据

群集清单保存 `publication_key`，用于验证 Ed25519 恢复发布签名。签名密钥仅由 control 持有，storage 不需要部署 key。不可变 JSON 发布记录位于 `recovery/history/<命名空间 UUID>/<记录 UUID>.json`，加速入口位于 `recovery/heads/<命名空间 UUID>.json`。

发布记录绑定命名空间、群集历史摘要、接管代次、发布修订、前序记录及其摘要、覆盖水位、新增恢复载荷和退役载荷。原生导出还附带后端目录前缀及根标记，根标记里的日志密钥仍由部署 key 包裹。每个新增载荷指定不可变意图、规范逻辑路径和完整字节摘要。签名消息为 `mokyu/storage/recovery-publication/v1`、一个零字节和按声明字段顺序编码的 JSON 发布记录。记录连同签名最多 128 KiB。入口采用前序比较更新，丢失入口不会删除历史证据。

恢复载荷始终等待对应布局的完整主副本，不继承普通业务的提前确认档。control 持久保存候选发布记录和逐介质的证据回执；分片与证据均齐全后，才在同一事务发布载荷、确认日志文件并推进水位。中断重试复用同一载荷和发布身份，证据按历史修订有界补齐，不能用已有正文回执代替恢复证据。

快照页、清单和索引沿用同一证据链。快照回执只接受已经结算的对应发布证明；切换当前快照还要求索引与检查点均已确认。日志与快照竞争发布位置时重试，不能跳过未完成的前序证明。

旧恢复文件进入清理队列后，先以当前检查点为依托发布退役证明，证明确认后才在 SQL 中退役对应载荷。中断时先续接未确认的退役证明，再开始新快照。实际删除仍等待读写租约和恢复任务的保护解除，按完整分片回执逐片删除；全部分片确认删除后才清理对应日志或快照的数据库记录。退役证明与存储删除均可重复执行，不能仅凭已加入清理队列就移除文件。

恢复扫描冻结来源的修改，分片页最多返回 128 项，历史证据页最多四项，并缓存最近一页用于重试。中断后分片从保存的目录前缀重新扫描，历史目录从头重扫，由 control 去重；不依赖文件系统返回顺序。候选、错头和损坏项保留诊断，不当作有效材料。

原库丢失时，`storage_recovery_catalogs`、`storage_recovery_cursors` 和 `storage_recovery_entries` 在新 control 数据库保存受信起点、游标及有界恢复暂存。恢复者沿受信群集历史核验发布签名、前序摘要和连续修订，再核对每个载荷的历史布局及独立片编号。`Part.digest` 覆盖整个载荷的全部帧，包括各帧末尾的公开摘要；它与帧内公开摘要的覆盖范围不同。物理映射包括载荷意图、逻辑路径、分片回执和发布状态，Mappings 通过 TLV 续接；其他帧也可携带至多 256 条的内联物理记录。业务记录沿用元数据日志的记录编码，直接解析到暂存表。

暂存每批最多 256 条记录、16 MiB 编码数据，单条最多 8 MiB。重复记录按身份和内容摘要核对；冲突使整批回滚，分页游标与该批记录一同提交。

物理记录同时保存所在日志的写入代次，暂存键包含代次和原始记录身份。不同代次可以使用相同序号；还原时按已验证的接管链和各代次截止序号排序，不能直接比较不同代次的序号或 UUID。退役状态保留载荷修订，迟到的旧记录不会重新发布对象。

记录进入暂存不代表正文依赖和业务恢复已经完成。目录遍历结束、有效发布链或足够数量的候选片均不能单独证明恢复点完整；还须验证实际载荷字节、所有依赖和覆盖水位。启动时磁盘用量在后台核对，`accounting_ready=false` 表示占用尚未确认，新写入暂停，已有文件仍可按授权读取。

读取和修复使用载荷发布时的布局。改变群集策略只影响新写入；重建核验新片回执后才切换，旧片保留到读租约和恢复引用释放。不要用当前群集的片数或并发来解释旧文件。可选宽度、确认方式和默认参数见[存储群集](storage-clusters.md#写入读取与修复)。
