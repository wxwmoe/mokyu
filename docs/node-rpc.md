# 节点 RPC

control 在 `instance.listen_control` 同一端口提供管理 HTTP 和 gRPC。协议定义为 [`proto/node.proto`](../proto/node.proto)，包名 `mokyu.node.v1`；节点 RPC 不经过管理 API 的 Cookie、JSON 或响应压缩中间件。反向代理必须保留 gRPC 路径、HTTP/2、请求元数据和响应 trailers，并禁止缓存。

## 身份与限制

节点凭据由管理员的 `cluster create` / `cluster rotate` 取得，见 [CLI](cli-reference.md)。每次 RPC 都携带下列 metadata，由 control 验证当前部署、启用状态、节点角色、凭据代次和凭据。

| Metadata | 值 |
| --- | --- |
| `x-mokyu-deployment-id` | 部署 UUID |
| `x-mokyu-node-id` | 节点 UUID |
| `x-mokyu-node-role` | `data` 或 `worker` |
| `x-mokyu-credential-generation` | 正整数凭据代次 |
| `authorization` | `Bearer <credential>` |

拒绝重复身份字段；全部 metadata 键和值合计最多 4 KiB。Unary 响应最多 4 MiB，SyncNode 请求最多 1 KiB，读取请求最多 128 KiB，NodeSession 消息最多 64 KiB；在解码之前检查身份格式和独立并发额度，额度持续到响应结束或取消。开始请求的服务端期限为 15 秒。节点凭据不授予管理 API 权限。

## 方法

| 方法 | 请求与响应 |
| --- | --- |
| `NodeControl/SyncNode` | Unary；提交当前 `run` 和最多五个 `cached` 配置修订，返回运行状态、全部当前修订及未命中配置 |
| `NodeReads/OpenRead` | Unary；按路由、身份、条件、`include` 与 `cached` 返回对象结果及首个读取窗口，仅允许 data |
| `NodeReads/ReadWindow` | Unary；沿当前读取游标取下一窗口，校验运行权、读取保护和载荷修订 |
| `NodeReads/ReportRead` | Unary；报告当前读取窗口内最多 16 个来源段，请求持久后端复核，仅允许 data |
| `NodeSessions/NodeSession` | 双向流；首条必须为 Hello，收到 Welcome 后发送 Pulse 并等待匹配序号的确认 |

配置分区为 `requests`、`uploads`、`metrics`、`maintenance`、`io`，不含管理 `web` 设置。`cached` 只表示已持有的配置修订，不替代任何身份或租约检查；缺失或修订不符时，在同一 SyncNode 响应内补全。Settings 的 JSON 字节使用对应运行设置的现有结构。

## 读取计划与缓存

`include` 必须明确指定：`OBJECT` 请求对象信息，`MAPPING` 请求正文读取计划及其必要依赖；HEAD 只接受 `OBJECT`。control 在同一事务内检查权限、条件和 Range，选择物理来源并登记保护，再返回有界结果。节点完成初始化后，首次 OpenRead 即可取得访问远端 S3 所需的对象映射、存储连接及所需块密钥；DNS、TLS 和会话建立另计。

`cached` 最多 256 项，每项包含材料类型、ID 和 32 字节修订。修订绑定部署、用途、身份与具体内容；响应明确给出 JSON 材料或 `reuse`。节点须在请求期间持有声明的材料，收到 `reuse` 时只能使用对应修订。桶已缓存而对象未缓存时，只补齐对象及未持有的依赖；配置、权限和来源有效性仍按当前状态检查。

完整正文缓存使用 `body` 提示，绑定正文检查状态、对象、完整映射、存储修订、表示和压缩策略。客户端在 RPC 期间固定候选；control 每次验证当前权限和来源，命中时不申请读取保护或 S3 I/O 额度。任一必要修订变化时，同次响应提供读取计划。identity 正文可用于 Range 或派生 HTTP 压缩体；inline 拒绝未验证正文，off/background 仍须匹配当前存储策略。请求中的 access key 只用于内部准备；data 必须使用返回的用户密钥完成原请求签名校验后，才向外呈现结果或开始正文 I/O。worker 无权调用此接口。

节点正文缓存使用 `instance.response_cache_size` 的共享预算、热点准入和 CLOCK 淘汰；候选、版本证明和在途正文持有均计费。仅接纳完整首窗口、最多 64 段和 16 个存储版本的合格小对象，超限及多窗口对象继续流式读取。后台检查失败或跳过后不再复用该正文；取消、未完成来源和无收益压缩体不入缓存。路由索引只定位候选，不替代授权；缓存响应仍受节点运行权与读取空闲期限约束。

区块磁盘缓存遵循来源的 `cache_enabled`、实例容量和条目限制；inline 或后台核验通过后，使用有界任务填充。命中仍遵循当前来源计划和读取校验策略，坏缓存先失效并回源，不能据此直接隔离后端。缓存索引重新加载、pin、删除失败计费和文件路径见[存储格式](storage-format.md#本地目录和缓存)。

桶路由允许匿名别名直接提供桶名与完整对象路径；签名请求不能使用该改写。公开 Web 路由使用已登记域名，支持其明确登记的端口。HTTP 调用方保留原始签名路径和查询参数，由 s3s 验证完整请求；错误签名优先于对象存在性、条件和 Range 结果。

窗口默认最多 1024 段、目标响应 1 MiB；调用方可降低 `max_items` 和 `max_bytes`。每个节点最多 256 个有效读取，每个读取最多保留两个窗口，可在处理当前窗口时预取下一窗口。来源包括独立区块、区块包、raw 和共享暂存；本机唯一来源仅交给所属节点，其他节点得到待就绪结果。

OpenRead 使用稳定 `operation_id`；同一运行权下重放同一请求会复用已提交的保护和窗口，参数变化则拒绝。ReadWindow 以读取身份和偏移重放已保存窗口。响应丢失不会分配第二份同操作读取；HEAD、条件未满足、空对象、权限拒绝及正文缓存命中均不获取正文 I/O 许可。

读取保护有效期为 90 秒，受限存储的读许可为 60 秒。一个许可只允许串行执行该存储上的读取；同时读取需分别取得许可。Pulse 的 `renew` / `release` 合计最多 256 项，确认逐项返回结果；已过期的资源不能续期复活。释放窗口解除其精确来源保护，释放读取同时释放窗口及关联存储许可。

节点运行上下文统一登记资源句柄并批量续期，最多保留 8192 个句柄；同一许可复用原句柄，最后一个持有者退出时通知 Session 释放。大量资源分成多批连续推进，释放失败在重连后重放。句柄绑定运行权和本地单调时钟期限，运行权失效、续期被拒绝或本地期限已过后禁止继续使用；迟到确认不能恢复句柄。

节点读取器保留当前与预取窗口，已消费窗口确认释放后才推进下一次预取。存储连接随对应材料复用，全局读取额度先于单许可额度取得。区块解码复用共享解压池，Pack 使用独立内存预算；正文切片继续持有其内存额度。取消请求会停止预取，已经开始的阻塞解码保留 CPU、内存与读取保护，直至实际工作结束。

HTTP 压缩与 Pack 解码分别使用剩余内存预算的一半，避免编码器占用上游解码所需的额度。压缩繁忙且请求允许 identity 时，在 OpenRead 前选择 identity；请求禁止 identity 时不改变其接受范围。正文流直到压缩结束仍检查运行权和读取空闲期限，运行权失效后不能继续完成响应。

普通读取按存储策略执行 inline、background 或 off 摘要检查；解密认证与本机唯一来源校验仍必须完成。后台摘要与单机共用执行器，最多 4 个任务、8 MiB 保留数据；CPU、队列或内存繁忙时记录为未验证，不将跳过当作成功。完整 raw 响应检查实际返回的全部字节，部分 raw 响应由 worker 复核完整后端来源。

ReportRead 绑定当前运行权、有效读取与窗口，下标只引用该窗口的独立区块、Pack 或已上传 raw。重复报告同一窗口来源复用任务身份；control 只排入持久复核，不凭报告直接隔离。复核任务最多保留 64 个待运行、运行中或暂停项，繁忙时按读取容量退避。worker 先检查后端命名空间和完整内容；健康来源完成检查，确认损坏时才按来源快照隔离。网络错误、命名空间不符和过期快照不能成为隔离证据。

## 会话和重连

每次进程启动生成新的 `boot_id`，一次待确认接入使用固定 `connection_id`。Hello 包含协议号 1、boot ID、connection ID 和最后获知的 `previous_epoch`；初次为 0。Welcome 返回 `run={boot_id,fence}`、会话 epoch、剩余有效毫秒数和配置修订。

会话有效期为 90 秒，数据库时钟决定到期。Pulse 的正整数 sequence 必须严格递增，确认后续期；流上 30 秒没有新 Pulse 时关闭连接。`draining` 一旦设为 true，同一 boot 不可撤销。客户端用请求发出时的单调时钟扣除传输耗时及 2 秒余量，不能把到期时间直接换成本机墙上时钟。

每次成功接入都会推进 epoch，旧流不能继续心跳。相同 boot 在有效期内重连保留业务 fence；过期重连会更换 fence。Welcome 丢失时，用相同 connection ID 重试可接入其他 control；获知新 epoch 后再创建下一次接入。新的 boot 须等待前一个 boot 过期，已退役的 boot 不能再次成为当前实例。每代凭据的 boot 历史达到 4096 项时，由管理员轮换凭据。

会话存在于共享 PostgreSQL 中，各 control 使用相同规则接管。流消息不构成业务提交记录。SyncNode 不续期会话，凭据轮换或节点禁用立即阻止后续请求。

会话客户端每 10 秒发送应用心跳，确认最多等待 30 秒且不超过本地运行权截止时间。断线后先尝试恢复，连续失败以 0.5～30 秒抖动退避；DNS 移除当前地址时也重新选择连接。每次接入后先 SyncNode，配置修订变化时只拉取缺少的分区。配置整体校验通过后才替换快照，拒绝重复、缺失或倒退的修订；增大单流内存需求的配置需要重启后重新分配预算。

重连保留同一有效运行权句柄，已到期的句柄不能被后来的确认复活。新的 fence、凭据拒绝、停止或驱动取消会使旧句柄失效。排空立即停止本地新工作准入，同时保留心跳和恢复连接；维护状态不撤销仍有效的运行权。仅 Session 中断时，持有有效运行权的调用仍可使用独立 Unary 连接，由相应业务 RPC 检查当前权限。

## 地址选择

客户端要求 HTTPS 域名 origin，不接受 IP、用户信息、路径或 query。解析完整 A 集合（最多 32 个），按 TTL 刷新，刷新间隔限制在 1～300 秒；DNS 失败时仅在上一次集合到期后的 300 秒内继续使用已知地址。

Unary 在可用地址间轮询，每个地址复用自己的 Channel；失败地址按退避暂停选择。NodeSession 使用独立 TCP/TLS 连接。连接实际 IP 时，仍使用原域名做 TLS SNI、证书验证与 HTTP authority。连接期限 3 秒，每次尝试最多 5 秒，整个操作最多 15 秒，传输失败最多尝试 3 个地址；`Unavailable`、`DeadlineExceeded` 和可识别的客户端传输超时进入有限重试，服务端主动取消不重试。

暂时没有读取、窗口或存储并发额度时，control 返回带 `mokyu-retryable: read-capacity` 的 `ResourceExhausted`。客户端保持操作身份，在原 15 秒总期限内退避重试，不把业务繁忙记为源站故障。消息大小和单次读取资源数量超限不带该标记，直接返回错误。

| gRPC 状态 | 处理 |
| --- | --- |
| `Unauthenticated` | 身份或凭据无效，停止使用并由管理员恢复 |
| `PermissionDenied` | 节点被禁用、角色不适用或部署不在群集模式 |
| `Aborted` | 其他 boot/会话已接管，或心跳序号过旧 |
| `FailedPrecondition` | 协议不支持、运行租约到期或 boot 已退役 |
| `ResourceExhausted` | 元数据、并发或 boot 历史超限 |
| `Unavailable` / `DeadlineExceeded` | 在有限期限和退避内尝试其他地址 |

消息长度超限也可能由 gRPC 解码器返回 `OutOfRange`。业务身份和状态错误不应触发地址轮换重试。

代理返回的 HTTP 429、502、503、504 转为 `Unavailable`，在解码正文前丢弃 HTML 错误页；HTTP 401/403 保留认证/权限失败语义，不轮换重试。
