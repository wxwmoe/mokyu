# 节点 RPC

control 在 `instance.listen_control` 同一端口提供管理 HTTP 和 gRPC。协议定义为 [`proto/node.proto`](../proto/node.proto)，包名 `mokyu.node.v1`；节点 RPC 不经过管理 API 的 Cookie、JSON 或响应压缩中间件。反向代理必须保留 gRPC 路径、HTTP/2、请求元数据和响应 trailers，并禁止缓存。

## 身份与限制

节点凭据由管理员的 `cluster create` / `cluster rotate` 取得，见 [CLI](cli-reference.md)。每次 RPC 都携带下列 metadata，由 control 验证当前部署、启用状态、节点角色、凭据代次和凭据。

| Metadata | 值 |
| --- | --- |
| `x-mokyu-deployment-id` | 部署 UUID |
| `x-mokyu-node-id` | 节点 UUID |
| `x-mokyu-node-role` | `data`、`worker` 或 `node` |
| `x-mokyu-credential-generation` | 正整数凭据代次 |
| `authorization` | `Bearer <credential>` |

拒绝重复身份字段；全部 metadata 键和值合计最多 4 KiB。Unary 响应最多 4 MiB，SyncNode 请求最多 1 KiB，读取请求最多 128 KiB，NodeSession 消息最多 64 KiB；在解码之前检查身份格式和独立并发额度，额度持续到响应结束或取消。开始请求的服务端期限为 15 秒。节点凭据不授予管理 API 权限。

## 方法

| 方法 | 请求与响应 |
| --- | --- |
| `NodeControl/SyncNode` | Unary；提交当前 `run` 和最多五个 `cached` 配置修订，返回运行状态、全部当前修订及未命中配置 |
| `NodeControl/ReportNode` | Unary；上报当前运行权绑定的递增序号、状态及可选配置快照，重复或过时序号不覆盖已保存报告 |
| `NodeControl/CloseNode` | Unary；结束当前 boot/fence，重复关闭安全；正常退出在排空后调用，旧运行权不能关闭新实例 |
| `NodeControl/PrepareRequest` | Unary；按 `include` 和 `cached` 准备签名凭据、桶和策略，可同时查询桶信息、桶列表或对象列表；仅允许 data |
| `NodeReads/OpenRead` | Unary；按路由、身份、条件、`include` 与 `cached` 返回对象结果及首个读取窗口，仅允许 data |
| `NodeReads/RefreshReads` | Unary；data/node 批量确认最多 32 个匿名公共读取快照及已有完整正文证明，返回分项结果和去重材料，不申请读取保护 |
| `NodeControl/ReportObservations` | Unary；批量上报 HTTP 压缩收益、已通过签名校验的凭据活动及区块/区块包访问统计，仅允许 data |
| `NodeReads/ReadWindow` | Unary；沿当前读取游标取下一窗口，校验运行权、读取保护和载荷修订 |
| `NodeReads/ReportRead` | Unary；报告当前读取窗口内最多 16 个来源段，请求持久后端复核，仅允许 data |
| `NodeSessions/NodeSession` | 双向流；首条必须为 Hello，Welcome 包含 control 实例 ID；Ping/Pong 检查连接，Pulse 维护运行权和资源，Notice 传递提示或缓存失效批次，Receipt 确认已应用的失效 |
| `NodeWrites/BeginWrite` | Unary；校验权限、创建写入上下文与租约并预留配额，返回存储材料；仅允许 data |
| `NodeObjects/ChangeObjects` | Unary；批量删除对象或修改单个对象的 canned ACL，持久保存操作结果；仅允许 data |
| `NodeWrites/PrepareChunks` | Unary；批量领取或复用区块，保存上传目标与编码参数，返回所需存储、密钥及上传许可 |
| `NodeWrites/CommitChunks` | Unary；确认整批上传完成并建立引用，可按批次乱序完成 |
| `NodeWrites/PrepareRaw` | Unary；校验完整文件身份、预留配额、查询去重并分配物理身份；远端上传另取得许可 |
| `NodeWrites/CommitRaw` | Unary；确认 raw 来源已达到所选持久化条件并建立引用，重复确认返回相同回执 |
| `NodeWrites/CheckRawFiles` | Unary；按当前运行权检查最多 128 个本地 raw 文件的保留和回收状态；仅允许 data |
| `NodeWork/Exchange` | Unary；提交上一批任务结果并领取下一批工作，返回所需材料和任务保护 |
| `NodeWork/ReadMigration` | Unary；取得任务绑定源版本的首个读取窗口，只允许候选所属节点和有效任务执行权 |
| `NodeWrites/PrepareTail` | Unary；为 chunks 分片的未闭合尾部预留共享 staging、配额和上传许可 |
| `NodeWrites/CommitTail` | Unary；确认尾部持久化并建立片段映射，重复确认复用同一结果 |
| `NodeWrites/PublishWrite` | Unary；核对完整性、条件和配额，原子发布对象并保存终态回执 |
| `NodeWrites/WriteStatus` | Unary；按节点与操作身份查询写入状态，不返回存储凭据 |
| `NodeWrites/AbortWrite` | Unary；取消当前运行权持有的写入，同事务释放写租约和预留配额 |

配置分区为 `requests`、`uploads`、`metrics`、`maintenance`、`io`，不含管理 `web` 设置。`cached` 只表示已持有的配置修订，不替代任何身份或租约检查；缺失或修订不符时，在同一 SyncNode 响应内补全。Settings 的 JSON 字节使用对应运行设置的现有结构。

## 会话通知与状态报告

node 具备 data 与 worker 的接口权限。每个 API 节点维持一条主要 NodeSession；control 通过 PostgreSQL 协调通知，无需彼此建立节点连接。

任务、运行设置和维护状态变化合并为每条连接最多每秒一条普通 Notice。配置提示携带分区修订，节点只在需要时使用 SyncNode；共享任务提示发往 worker/node，本机任务只提示所属节点，提示不改变任务领取权限。control 共用一个 PostgreSQL 监听连接接收普通提示和缓存事件。对象发布、ACL、删除、桶和域名、存储策略及已确认来源健康变化与业务事务一起保存事件和目标代次；PostgreSQL 通知唤醒 control，持久扫描补偿遗漏并接管未确认目标。缓存通知按 50 ms 窗口聚合，每帧最多 32 项；发送队列和进程内存有界。

节点先隔离旧授权和在途填充，再以 Receipt 批量确认事件 ID；确认不要求后台刷新成功。重复投递只补确认，不能再次驱逐已经刷新的快照。有效且仍驻留的条目立即排队刷新元数据，前台可共用正在刷新的结果；正文继续复用，不为刷新预取 S3 正文。无条目或已过期时不主动预取。队列满、刷新失败和较新的通知都不能让旧授权恢复可用。

Receipt 最多聚合 50 ms、128 项，也可搭载 Pulse；应用失效后才确认，不等待后台刷新。Notice、Receipt、Ping/Pong 和 SyncNode 不续租。等待 PulseReply 或 SyncNode 时继续处理通知。服务端三十秒未收到入站消息，或已发送事件三十秒未收到应用确认时关闭会话；待确认数超过 1024 同样要求重建。客户端在重连 Hello 前隔离公共缓存授权，重新同步后才恢复快路径；异步校验、硬过期、来源校验和资源租约继续生效。

目标绑定节点与会话代次；切换到新代次时，旧代次隔离后的目标记为退役，不冒充应用确认。control 的持久扫描继续处理未确认目标，发起 control 退出不丢失已提交的通知。

control 状态中的 `notifications` 提供订阅状态、重连次数、会话数、队列字节、已发送和已应用条数、背压次数、普通提示与提示丢弃计数；节点 `public_read_cache` 另提供 `pending_checks` 和 `pending_refreshes`。节点状态还包含 `cors_cache` 和 `read_checks`，分别报告前台 CORS 缓存与后台摘要校验。应用确认与刷新完成分别计数，不能把入队或发送视为已生效。

驻留通知刷新与持有正文证明的周期刷新通过 `RefreshReads` 合并，每批最多 32 项；周期刷新只合并已经排队的候选，通知刷新优先，缺少正文证明时继续使用 `OpenRead`。普通冷读不等待凑批。control 最多收集 5 ms，再按集合查询确认路由、权限、元数据、策略和来源；开始查询后到达的请求进入下一组。每个调用者独立验证运行身份，批次不共享租约。control 的 `read_refresh` 提供请求数、合并组数、候选项数、查询路由数、材料缓存命中及排队项数。

状态报告使用独立 Unary，请求最多 96 KiB，其中状态最多 30 KiB、可选元数据最多 60 KiB。报告绑定当前 boot/fence 和递增序号，同一 boot 换连接不重置报告。元数据只在报告接受后视为确认；重复或过时序号返回 `accepted=false`，可在下一份报告中重新携带。诊断请求不续租，也不代替业务确认。关闭会保留已结束 boot 的记录，不能靠重连复活；突然掉线仍由运行租约到期处理。

## 读取计划与缓存

`include` 必须明确指定：`OBJECT` 请求对象信息，`MAPPING` 请求正文读取计划及其必要依赖，`POLICY` 请求桶所用存储的读取策略；HEAD 接受 `OBJECT` 和 `POLICY`。读取策略包含存储身份、修订、读取校验策略、有效 CORS 缓存开关及公共快照的刷新间隔和最大有效期，不携带存储连接或密钥。control 在同一事务内检查权限、条件和 Range，选择物理来源并登记保护，再返回有界结果。节点完成初始化后，首次 OpenRead 即可取得访问远端 S3 所需的对象映射、存储连接及所需块密钥；DNS、TLS 和会话建立另计。

`cached` 最多 256 项，每项包含材料类型、ID 和 32 字节修订。修订绑定部署、用途、身份与具体内容；响应明确给出 JSON 材料或 `reuse`。节点须在请求期间持有声明的材料，收到 `reuse` 时只能使用对应修订。桶已缓存而对象未缓存时，只补齐对象及未持有的依赖；配置、权限和来源有效性仍按当前状态检查。

`RefreshReads` 请求共用 `run` 和 `cached`，每项包含路由及可选完整正文证明。响应按原顺序返回 403/404 或当前对象结果，公共材料集中去重；仅确认元数据时不表示完整 GET 来源已确认。正文证明不匹配、来源不可确认或结果超限时，实际 GET 继续使用 `OpenRead`，不预取正文、不保留负授权缓存。control 只短暂缓存按当前配置指纹匹配的不可变存储材料（最多 8 MiB、128 项、1 秒），仍需每轮查询当前数据库状态。

完整正文缓存使用 `body` 提示，绑定正文检查状态、对象、完整映射、存储修订、表示和压缩策略。客户端在 RPC 期间固定候选；control 在每次 OpenRead 中验证当前权限和来源，命中时不申请读取保护或 S3 I/O 额度。任一必要修订变化时，同次响应提供读取计划。identity 正文可用于 Range 或派生 HTTP 压缩体；inline 拒绝未验证正文，off/background 仍须匹配当前存储策略。请求中的 access key 只用于内部准备；data 必须使用返回的用户密钥完成原请求签名校验后，才向外呈现结果或开始正文 I/O。worker 无权调用此接口。

节点正文缓存使用 `instance.response_cache_size` 的共享预算、热点准入和 CLOCK 淘汰；候选、版本证明和在途正文持有均计费。仅接纳完整首窗口、最多 64 段和 16 个存储版本的合格小对象，超限及多窗口对象继续流式读取。后台检查失败或跳过后不再复用该正文；取消、未完成来源和无收益压缩体不入缓存。路由索引只定位候选，不替代授权；缓存响应仍受节点运行权与读取空闲期限约束。

相关存储均启用 `public_cache_validation=background` 时，匿名公共读取可在快照有效期内复用权限和元数据：HEAD、桶预检及有完整映射证明的 L1 正文命中可省略前台 OpenRead。仅有 HEAD 快照或正文未命中时，GET 仍通过 OpenRead 取得当前来源保护。快照使用公共元数据共享预算，有界异步刷新；有效期从原请求开始计时，刷新失败不延期。已观察到的对象、桶或存储变化会失效相应快照，会话重新建立后重新确认。签名、预签名、条件请求、`no-cache` 和 checksum 请求继续使用 OpenRead；后台校验允许的权限撤销延迟受最大有效期限制。

区块和 raw 磁盘缓存遵循来源的 `cache_enabled`、实例容量和条目限制，共享文件预算。区块在 inline 或后台核验通过后有界填充；raw 在 inline 校验时流式填充，复用同一文件输出，并发相同来源共用填充结果。命中仍遵循当前来源计划和读取校验策略，坏缓存先失效并回源，不能据此直接隔离后端。缓存索引重新加载、pin、删除失败计费和文件路径见[存储格式](storage-format.md#本地目录和缓存)。

桶路由允许匿名别名直接提供桶名与完整对象路径；签名请求不能使用该改写。公开 Web 路由使用已登记域名，支持其明确登记的端口。HTTP 调用方保留原始签名路径和查询参数，由 s3s 验证完整请求；错误签名优先于对象存在性、条件和 Range 结果。

节点 CORS 缓存按 `requests.cors_cache_size` 和 `cors_cache_entries` 计费，相同规则共享解析结果。桶修订和读取策略来自同次 OpenRead 或有效公共快照；规则变化立即使用返回的新规则，关闭缓存后直接解析当前规则。队列或预算不足时跳过填充，不等待缓存容量。

压缩收益和凭据活动复用有界后台队列，每类最多 256 项；重复项合并后以最多 64 项、16 KiB 的批次上报，HTTP 响应不等待上报。压缩结果只在编码完整结束后产生，使用固定策略版本；凭据最近使用时间按五分钟合并。control 在事务内校验 data 身份、运行权及维护状态，再写入当前可用对象的观测；重复上报不重复覆盖已有压缩结果。队列满、超时或失联可丢弃观测，后续访问可重新提交，不影响对象读取和发布。节点 HTTP 请求沿用统一请求 ID、完成/失败/取消及实际输出字节计数。

访问统计通过独立批次携带 `access_json`，聚合区块逻辑读取、Range、区块包实际下载、有效字节和成员访问；完整正文缓存命中与后台读取不登记用户访问。每节点最多 8192 项、一个在途请求，请求上限 2 MiB，客户端及服务端处理期限均为两秒；按 `metrics.access_flush_interval` 或容量唤醒发送，前台读取不等待统计。control 校验当前 data 运行权、数量和时间范围，只更新仍存在的来源。每个 boot 的递增序号和请求摘要防止重复加算；丢批、跳号和重启重置完整覆盖起点。所有启用 data 节点均有有效会话及新鲜报告时才推进群集覆盖时间，失联节点不能被其他节点的报告掩盖。统计属于性能观测，不作为授权、发布或损坏判断的依据。

窗口默认最多 1024 段、目标响应 1 MiB；调用方可降低 `max_items` 和 `max_bytes`。每个节点最多 256 个有效读取，每个读取最多保留两个窗口，可在处理当前窗口时预取下一窗口。来源包括独立区块、区块包、raw 和共享暂存；本机唯一来源仅交给所属节点，其他节点得到待就绪结果。

OpenRead 使用稳定 `operation_id`；同一运行权下重放同一请求会复用已提交的保护和窗口，参数变化则拒绝。ReadWindow 以读取身份和偏移重放已保存窗口。响应丢失不会分配第二份同操作读取；HEAD、条件未满足、空对象、权限拒绝及正文缓存命中均不获取正文 I/O 许可。

control 可通过 `replica_database` 分流公共读取的后续区块映射查询。OpenRead 和物理来源选择始终使用主库；ReadWindow 仅在主库记录该读取允许使用从库，且从库同一快照已看到对应读取标记和载荷修订时采用映射。签名读取、raw、暂存片段及已保存的重放窗口不依赖从库。池忙、未追平、超时或身份异常时沿当前游标回退主库，不增加节点 RPC 往返。

读取保护有效期为 90 秒，受限存储的读许可为 60 秒。一个许可只允许串行执行该存储上的读取；同时读取需分别取得许可。Pulse 的 `renew` / `release` 合计最多 256 项，确认逐项返回结果；已过期的资源不能续期复活。释放窗口解除其精确来源保护，释放读取同时释放窗口及关联存储许可。

节点运行上下文统一登记资源句柄并批量续期，最多保留 8192 个句柄；同一许可复用原句柄，最后一个持有者退出时通知 Session 释放。大量资源分成多批连续推进，释放失败在重连后重放。句柄绑定运行权和本地单调时钟期限，运行权失效、续期被拒绝或本地期限已过后禁止继续使用；迟到确认不能恢复句柄。

节点读取器保留当前与预取窗口，已消费窗口确认释放后才推进下一次预取。存储连接随对应材料复用，全局读取额度先于单许可额度取得。区块解码复用共享解压池，Pack 使用独立内存预算；正文切片继续持有其内存额度。取消请求会停止预取，已经开始的阻塞解码保留 CPU、内存与读取保护，直至实际工作结束。

HTTP 压缩与 Pack 解码分别使用剩余内存预算的一半，避免编码器占用上游解码所需的额度。压缩繁忙且请求允许 identity 时，在 OpenRead 前选择 identity；请求禁止 identity 时不改变其接受范围。正文流直到压缩结束仍检查运行权和读取空闲期限，运行权失效后不能继续完成响应。

普通读取按存储策略执行 inline、background 或 off 摘要检查；解密认证与本机唯一来源校验仍必须完成。后台摘要与单机共用执行器，最多 4 个任务、8 MiB 保留数据；CPU、队列或内存繁忙时记录为未验证，不将跳过当作成功。完整 raw 响应检查实际返回的全部字节，部分 raw 响应由 worker 复核完整后端来源。

ReportRead 绑定当前运行权、有效读取与窗口，下标只引用该窗口的独立区块、Pack 或已上传 raw。重复报告同一窗口来源复用任务身份；control 只排入持久复核，不凭报告直接隔离。复核任务最多保留 64 个待运行、运行中或暂停项，繁忙时按读取容量退避。worker 先检查后端命名空间和完整内容；健康来源完成检查，确认损坏时才按来源快照隔离。网络错误、命名空间不符和过期快照不能成为隔离证据。

## 会话和重连

每次进程启动生成新的 `boot_id`，一次待确认接入使用固定 `connection_id`。Hello 包含协议号 1、boot ID、connection ID 和最后获知的 `previous_epoch`；初次为 0。Welcome 返回 `run={boot_id,fence}`、会话 epoch、剩余有效毫秒数和配置修订。

运行权有效期为 90 秒，数据库时钟决定到期。Pulse 的正整数 sequence 必须严格递增；`renew_run=true` 才延长运行权并返回完整状态，否则只维护指定资源、返回运行权剩余时间。资源维护不延长通知消费代次。`draining` 通过运行权续租设置，一旦为 true，同一 boot 不可撤销。客户端用请求发出时的单调时钟扣除传输耗时及 2 秒余量，不能把到期时间直接换成本机墙上时钟。

每次成功接入都会推进 epoch，旧流不能继续心跳。相同 boot 在有效期内重连保留业务 fence；过期重连会更换 fence。Welcome 丢失时，用相同 connection ID 重试可接入其他 control；获知新 epoch 后再创建下一次接入。新的 boot 须等待前一个 boot 过期，已退役的 boot 不能再次成为当前实例。每代凭据的 boot 历史达到 4096 项时，由管理员轮换凭据。

会话存在于共享 PostgreSQL 中，各 control 使用相同规则接管。流消息不构成业务提交记录。SyncNode 不续期会话，凭据轮换或节点禁用立即阻止后续请求。

会话客户端在上行或下行连续 10 秒无活动时发送 Ping，持续双向消息会推迟 Ping；仅下行流量不能隐藏上行失联。Pong 返回同一递增 nonce，不访问数据库，也不证明运行权仍有效。Ping 和 Pulse 的确认最多等待 10 秒且不超过本地运行权截止时间。运行权和资源分别按剩余有效期的三分之一安排续期，运行权最多间隔 25 秒、资源最多 30 秒；释放短暂聚合约 20 ms 后发送。断线后先尝试恢复，连续失败以 0.5～30 秒抖动退避；DNS 移除当前地址时也重新选择连接。每次接入后先 SyncNode，配置修订变化时只拉取缺少的分区。配置整体校验通过后才替换快照，拒绝重复、缺失或倒退的修订；增大单流内存需求的配置需要重启后重新分配预算。

重连保留同一有效运行权句柄，已到期的句柄不能被后来的确认复活。新的 fence、凭据拒绝、停止或驱动取消会使旧句柄失效。排空立即停止本地新工作准入，同时保留心跳和恢复连接；维护状态不撤销仍有效的运行权。仅 Session 中断时，持有有效运行权的调用仍可使用独立 Unary 连接，由相应业务 RPC 检查当前权限。

## 写入

PrepareRequest 请求最多 128 KiB；`include` 从 `S3_CREDENTIAL`、`BUCKET`、`READ_POLICY` 中选择，至少一项且不能重复，`cached` 沿用读取材料的修订和持有规则。每次准备都确认当前凭据状态；返回凭据包含非负的 `revision`。准备不要求对象读取权限，也不创建 stream、对象、租约或配额预留。

`query` 可选择 `describe_bucket`、`list_buckets` 或 `list_objects`，与本次签名材料在同一 RPC 返回；节点校验完整 S3 签名和请求参数后才输出 `catalog_json`，游标校验错误同样等待签名确认。查询要求当前凭据和 `bucket.list` 权限，使用独立于上传的有界控制请求额度；缓存材料不替代本次授权。HeadBucket、GetBucketLocation、ListBuckets 和 ListObjectsV2 正常请求只需一次 PrepareRequest，不申请正文读取保护或访问对象存储。

对象列表每页 0–1000 项，桶列表每页 1–10000 项，均默认 1000；响应受 4 MiB 消息上限约束。对象列表游标绑定桶、前缀和分隔符；桶列表游标绑定凭据、前缀和地区。前缀、分隔符和起始键最多 1024 字节，游标最多 16 KiB。权限、凭据或节点运行权失效后不能凭缓存继续列出结果；断线可重试查询，分页不提供跨请求的固定快照。

`query.object_acl` 使用 `object.read` 权限，随签名材料一次返回对象的公开标志，不获取正文映射或存储凭据。GetObjectAcl 在签名验证后输出所有者与 canned ACL，缺失对象也等签名验证后报告。

ChangeObjects 在入站签名验证后执行，携带相同凭据修订、桶、操作 ID、最多 1000 个对象键和可选的 `public_read`。省略 `public_read` 表示删除；设置时必须只有一个键，要求 `object.acl` 权限。删除要求 `object.delete` 权限，键最多 1024 字节，请求最多 2 MiB。control 在一个短事务内重新校验授权、桶状态、维护状态和运行权，按键排序获取锁并提交全部有效删除；S3 DeleteObjects 的不支持字段仍逐项报告，Quiet 只省略成功项。删除只退役引用，物理回收继续遵守读租约和其他引用保护。

对象变更回执绑定节点、凭据代次、UUIDv7 操作 ID 和完整参数哈希，包括 ACL 的缺失对象结果。响应丢失后重试原操作只返回已保存结果，不影响随后覆盖的对象；参数变化被拒绝。首次调用的时间窗口为过去 15 分钟至未来 30 秒，回执至少保留一天；清理后旧操作不会重新执行。节点变更期间使对应对象及别名的本地公共快照失效，其他节点继续遵守已有缓存有效期。

CreateMultipart 与 AbortMultipart 在 control 完成准入或取消，并在同一事务保存节点、凭据代次、操作参数和结果。重试复用 UploadId 或取消回执，不重复占用活动上传名额；参数变化被拒绝。首次操作接受过去 15 分钟至未来 30 秒，回执至少保留一天。创建重验当前写权限、公开对象所需 ACL 权限、桶暂停状态和上传数量上限；取消校验上传所属凭据、桶、对象键和可选的发起时间。

ListMultipartUploads 和 ListParts 与当前凭据、桶材料合并为一次 PrepareRequest，按原 S3 marker/prefix/delimiter 规则返回有界列表。列表不延长上传期限；分片信息通过 JOIN 一次取得，不在节点逐分片查询。创建和列表沿用现有 checksum 算法及 FULL_OBJECT/COMPOSITE 规则。

UploadPart 通过 BeginWrite 的 `part={upload_id,number,algorithm}` 绑定上传所有者及分片代次，使用上传的元数据和 checksum 算法；每片最多 5 GiB。分片配额归属上传，替换中的分片保留原先成功的版本。写租约和上传许可续期同时检查当前分片代次与上传状态；被替换、取消或已开始完成的写入不能继续提交。

inline chunks 分片复用批量 PrepareChunks/CommitChunks，只有小于 4 MiB 的未闭合 CDC 尾部进入共享 staging。PrepareTail 绑定偏移、长度和 BLAKE3，先保存唯一位置及空间预留，再返回存储材料与许可；CommitTail 原子建立映射并保存确认状态。节点校验完整正文后才发布分片，PublishWrite 将分片引用与回执一起提交；失败的替换不撤销原分片，重放不会重复引用或扣配额。

UploadPart 开启写缓存时可以在所属节点持久确认后响应。raw 保留原生 Multipart 的本机分片文件，后台上传到对应远端分片；chunks 保存本机 raw，再按接受时的策略转换为最终区块和共享尾块。关闭缓存或容量不足而选择 fallback 时，raw 等待远端分片确认，chunks 直接完成流式分块；background 不额外上传整个 chunks 分片作为远端 raw。

BeginComplete 冻结所选分片并返回完成摘要，ReadComplete 每次取得最多 8 个受保护来源。节点将所选正文连续送入同一个 CDC 接收器，分片切分位置不改变最终区块边界。摘要的 `pending_sources` 表示仍需等待远端原生分片或其他节点的本机来源，等待期间不占前台上传内存槽位；沿用 300 秒等待上限和相同清单重试。ReadComplete 发现来源仍待共享时返回带 `mokyu-retryable: source-pending` 的 FailedPrecondition，节点在期限内每 3 秒重试同一窗口标识；永久来源错误直接失败。

重复 Complete 等待已有执行时，同一对象或桶的通知会唤醒本机等待者，通过 CompleteStatus 重新确认结果。通知不代表执行成功；未收到通知仍每 3 秒复查，沿用原总截止、清单和权限校验。取消等待释放本机等待项，不取消已接受的完成工作。

BeginWrite 请求最多 64 KiB；包含桶、对象键、服务凭据身份、必填的 `credential_revision`、对象元数据、公开标志和可选的已知长度。调用方先使用准备的凭据验证入站签名，再携带同一修订发起准入；修订为 0 与漏传不同。control 在创建写入前确认当前修订，并在同一事务内校验写入权限及公开对象所需的 ACL 权限、桶状态、维护状态和配额，绑定对象写令牌、存储策略与块密钥。准入返回实际桶和 stream 身份；存储材料支持 `cached`，不重复发送匹配修订的连接配置。

CopyObject 使用源 OpenRead 的 `include=[OBJECT,PROTECTION]` 取得元数据和读保护，空对象同样返回保护；不请求映射时不返回存储或密钥。该组合只用于有服务凭据的 GET 读取。BeginWrite 的可选 `copy_read_id` 绑定同一运行实例的完整源版本和源桶读取权限，返回是否能直接复制区块引用。

同存储 chunks 使用 CopyChunks，每批复制最多 500 条映射并原子记录结果；批次编号和偏移必须连续，重复批次不重复建立引用。跨存储或涉及 raw 的复制经 ReadWindow 流式读取并复用写入流水线，始终校验来源完整性，不受普通读完整性档位关闭的影响。复制保持源 ETag 和校验和，元数据遵循 COPY/REPLACE，ACL 独立设置。发布时重验源和目标权限、源读保护及绑定版本；源对象被覆盖后仍复制受保护版本。已发布回执不因源保护后来到期失效。

PrepareChunks 每批最多 128 个区块、32 MiB 原始数据；批次编号从 1 开始，偏移连续，最多保留 4 个未完成批次。节点先计算原始摘要及压缩后明文的摘要、长度和压缩标志，再请求计划。control 在 S3 PUT 前保存物理身份、完整编码参数及 nonce；同批重复内容只分配一个物理编码。任一内容被其他未完成写入占用时整批回滚并返回可重试容量繁忙。重放要求描述符完全匹配；已经完成的批次只返回完成回执。

上传目标所需的存储和块密钥沿用 `cached`。`parallelism` 默认为 1，上限 16；配置存储上传并发限制时，计划批量返回实际可用的 `STORAGE_WRITE` 许可，可能少于请求数。新批次按准入时与当前限制中的较小值分配，配置下调不撤销已经取得且仍有效的许可。节点不得超出许可数量同时上传，许可通过 NodeSession 续期，过期或释放后必须重新取得；纯复用不占上传许可、不分配 nonce。等待下一批容量时，节点应继续完成已经准备的批次。

CommitChunks 携带本批新增物理编码的 ID 和密文字节摘要，省略复用区块；同批重复引用只确认一次物理上传。成功后建立完整引用、释放该批上传许可，并压缩为幂等回执；批次可以乱序完成，重复确认不得改变摘要。PublishWrite 包含总长度、ETag、校验和与条件，核对所有批次完成、连续映射及可读来源后原子发布。重试返回同一终态结果；WriteStatus 可查询该结果，AbortWrite 不撤销已经发布的对象。

HTTP PUT 的可靠 chunks 接收按 CDC 边界流式形成最多 8 MiB 的批次，同时保留两个批次；上传受节点额度和实际返回的存储许可共同限制。完整正文、流式签名尾块和校验和通过后才调用 PublishWrite；零字节对象不调用区块接口。发布使本节点对应对象及其别名的公共快照失效。已经确认的发布回执不因写租约随后结束而改判失败。

inline raw 普通 PUT 先使用节点本地请求暂存空间接收并校验完整文件，上限 5 GiB。PrepareRaw 包含长度、16 字节 MD5、`local`，以及 inline 整文件去重需要的 32 字节 BLAKE3；同一操作必须重放相同输入。去重命中直接建立引用并返回已确认状态，不上传对象、不占存储上传许可。未命中且 `local=false` 时，control 先持久化最终 raw 身份，再返回上传许可；节点流式 PUT 到最终 S3 key，成功后调用 CommitRaw，最后 PublishWrite。该流式 PUT 将存储的 `request_timeout` 用作无传输进展或等待响应的超时，持续传输不受整文件总时长限制；失败重试从本地文件重新发送，仍受重试次数和期限限制。PrepareRaw 与 CommitRaw 都可重试，上传许可同样通过 NodeSession 续期；取消或过期不会抹去外部上传的清理记录。请求暂存与本地缓存共享磁盘容量和最低剩余空间约束，暂存空间不足返回可重试错误。

普通 PUT 启用写缓存时使用 `local=true`，节点先同步本地文件和目录，再调用 CommitRaw 保存来源、所属节点和必须完成的排空任务，最后发布对象。raw 后台去重先计算摘要并查询重复来源，再上传；chunks 按接受时的编码策略在原节点执行 CDC，可直接生成最终区块包。唯一缓存只能由所属节点处理，同节点读取校验本地文件，其他节点沿用短暂等待和可重试响应。节点本地持久化不提供节点丢失冗余。

写缓存遵守节点总容量和存储的 `upload_cache_size`。满额使用 `fallback` 时关闭此次提前确认；已知长度的 inline chunks 请求直接走有界内存流水线。`reject` 返回 503、`Retry-After: 60` 和 `Cache-Control: no-store`，不覆盖原对象。原节点的排空在停止准入后仍可推进；任务结果、任务保护和上传许可通过 Exchange 与 NodeSession 恢复，过期的执行结果不能发布。

Exchange 的 `max_items` 范围为 1–64；携带完成结果时可设为 0，仅确认结果而不领取工作。节点在等待下一次本地额度前先释放已完成任务的后端许可；缓存上传持续持有本机内存和 I/O 额度，直至完成回执获确认。

同一存储、同一所属节点的 raw 缓存任务合并领取，每批最多 64 个文件、64 MiB；超过字节窗口的单个文件独立成批。摘要计算和上传结果逐项记录，共用批次回执和上传额度。每个文件保留原任务身份，批次内任一任务暂停或失去执行权时停止续租，旧结果不能部分发布；其他任务可重新领取。摘要锁繁忙时整批回滚并有界退避，避免持有一把摘要锁等待另一把。

CheckRawFiles 每次接收最多 128 个不重复的 UUID，返回 `pending`、`protected`、`cached` 或 `removable`。节点在首次写入前恢复持久文件的占用，随后定期对账；前两种状态保留文件，`cached` 可转为可淘汰读缓存，`removable` 才可删除。上传完成并不立即解除仍有效的读取或任务保护；删除成功后才释放对应磁盘占用，避免断线或取消丢失唯一来源。

CheckLocalFiles 对 Multipart 文件返回同样的有界状态记录，所属节点的 `pending` 项携带存储和长度以恢复写缓存占用。远端确认后释放上传额度，物理文件仍受分片和读取引用保护；只有 `removable` 项可以删除。

写入 `operation_id` 使用 UUIDv7。首次准入接受过去 15 分钟至未来 30 秒内的时间戳；节点应同步系统时钟。相同操作与相同参数重放原上下文，参数变化返回 `AlreadyExists`。活动写入重放会重验原授权；同一节点的其他 boot 或凭据代次不能继续该写入。WriteStatus 可查询该节点的历史回执，返回 `WRITE_ACTIVE`、`WRITE_ABORTED`、`WRITE_EXPIRED` 或 `WRITE_PUBLISHED`；stream 被回收后仍保留终态回执，桶和 stream 身份可能为空。

每节点最多 4096 个有效写入。`WRITE_PROTECTION` 为 90 秒租约，复用 NodeSession 的批量续期与释放，不能恢复已经过期的租约；释放会取消未发布的写入。取消可重复执行，回执不随 stream 回收丢失；准入时分批清理超过一天且无有效租约的回执。清理后的操作时间已超出首次准入窗口，不能重新执行。

后台 CDC 候选沿用 PrepareChunks/CommitChunks。接受的策略启用 pack 时，`packing_json` 返回当前批次的最终 pack 与独立编码候选、nonce 和分组；节点直接用已验证的原始缓冲编码上传，不先上传临时独立区块。CommitChunks 用 `packed_json` 确认选中输出，不能同时提交普通区块回执；control 核对目标、覆盖范围和任务所有权后原子建立引用。已接受的压缩和打包策略保持不变，管理端暂停新建 pack 时禁止发布新的 pack；未选输出在批次任务完成后进入正常回收。

存储迁移通过 Exchange 领取任务，ReadMigration 一次返回源对象、首窗口、缺少的存储和密钥材料以及读取保护。后续窗口复用 ReadWindow；worker 只能继续自己持有的读取，不能调用普通 OpenRead 或 BeginWrite。目标写入复用 PrepareChunks/CommitChunks 或 PrepareRaw/CommitRaw，保持源 ETag、校验和和元数据，并按目标策略执行分块、压缩和加密。

迁移候选须取得共享存储确认；未封存候选在任务接管时废弃，已封存候选可在新执行权下继续发布。最终 Exchange 重新检查源和目标版本及配额，原子完成 copy/move 与任务进度并保存回执。暂停、过期或其他节点的旧结果不能发布；暂停后的任务保护拒绝续期，并释放存储额度。每个存储沿用 `migration_concurrency` 和 `migration_byte_budget`。迁移和 CDC 转换的整文件传输由进展超时和有效租约约束，不使用 `maintenance.max_duration` 作为整文件截止时间。

节点可以复用编码、pack、rewrite、完整检查、raw 处理和迁移中的已验证字节回填本机读缓存。目标候选等待 CommitChunks、CommitRaw 或 ExchangeWork 的成功回执，丢失响应沿用原 RPC 重试确认；候选等待有界，超时可放弃缓存而继续确认任务。候选发布前核对运行权及已收到的存储配置代次；后台冷接纳不会因扫描加热或淘汰前台热点。完整检查仍读取真实后端，独立 worker 不会替其他 data 预热缓存。

后台批次已领取后，本机 I/O 或共享内存不足时立即释放本批任务保护并退避，保持任务可重新领取，不能把本机繁忙记为后端失败。缓存上传在领取前取得本机容量，并持有至结果确认。raw 摘要计算在 CPU 忙时同样退让；编码流水线保持先读取后 CPU 的顺序。pack、编码重写、raw 摘要和存储扫描按条目与字节限制成批，使用后端请求超时和有效租约；`maintenance.max_duration` 不作为这些有正文 I/O 批次的整体截止时间。完整性检查保留存储策略的批次超时。

## 地址选择

客户端要求 HTTPS 域名 origin，不接受 IP、用户信息、路径或 query。解析完整 A 集合（最多 32 个），按 TTL 刷新，刷新间隔限制在 1～300 秒；DNS 失败时仅在上一次集合到期后的 300 秒内继续使用已知地址。

Unary 在可用地址间轮询，每个地址复用自己的 Channel；失败地址按退避暂停选择。NodeSession 使用独立 TCP/TLS 连接。连接实际 IP 时，仍使用原域名做 TLS SNI、证书验证与 HTTP authority。连接期限 3 秒，每次尝试最多 5 秒，整个操作最多 15 秒，传输失败最多尝试 3 个地址；`Unavailable`、`DeadlineExceeded` 和可识别的客户端传输超时进入有限重试，服务端主动取消不重试。

暂时没有读取、窗口或存储并发额度时，control 返回带 `mokyu-retryable: read-capacity` 的 `ResourceExhausted`；区块领取、未完成批次窗口或上传额度繁忙使用 `write-capacity`。客户端保持操作身份，在原 15 秒总期限内退避重试，不把业务繁忙记为源站故障。消息大小或单次资源数量超限不带该标记，直接返回错误。

| gRPC 状态 | 处理 |
| --- | --- |
| `Unauthenticated` | 身份或凭据无效，停止使用并由管理员恢复 |
| `PermissionDenied` | 节点被禁用、角色不适用、部署不在群集模式或业务权限不足 |
| `Aborted` | 其他 boot/会话已接管，或心跳序号过旧 |
| `FailedPrecondition` | 协议不支持、运行租约到期、boot 已退役，或读取来源/载荷修订已失效；不惩罚 control 地址健康状态 |
| `ResourceExhausted` | 元数据、并发、写入数量、存储配额或 boot 历史超限 |
| `AlreadyExists` | 同一写操作的参数发生变化 |
| `NotFound` | 指定写操作或桶不存在 |
| `Unavailable` / `DeadlineExceeded` | 在有限期限和退避内尝试其他地址 |

消息长度超限也可能由 gRPC 解码器返回 `OutOfRange`。写入准入的权限、桶、配额及请求错误通过 `mokyu-s3-code` 响应 metadata 保留 S3 业务码，调用方不依赖错误文案区分配额不足和节点容量不足。业务身份和状态错误不应触发地址轮换重试。

代理返回的 HTTP 429、502、503、504 转为 `Unavailable`，在解码正文前丢弃 HTML 错误页；HTTP 401/403 保留认证/权限失败语义，不轮换重试。
